Trees & BST

Recursion on a branching structure

1. Trees are recursive data

▶ YouTube reference — the video for this lesson

A tree is a node with a value and pointers to children; a binary tree has at most two. The key insight is that every subtree is itself a tree, so every tree problem is a recursion problem: solve it for the left and right children, combine the results at the current node. Depth is one plus the deeper child's depth, and the size is one plus both children's sizes. Once you see the subtree structure, the recursion writes itself.

2. Traversals: four orders, one idea

▶ YouTube reference — the video for this lesson

Traversal order is just when you visit the node relative to its children: preorder visits the node first, inorder between the children, postorder last, and level order visits breadth-first with a queue. Inorder on a binary search tree yields the values sorted — that single fact powers validation, kth-smallest and recovery problems. Iterative traversals use an explicit stack and mirror the recursion exactly; learn the recursive form first, then the iterative one for interviews that demand it.

3. The BST property is a search superpower

▶ YouTube reference — the video for this lesson

In a binary search tree, every left descendant is smaller and every right descendant is larger than the node. That ordering turns search into a walk: go left if the target is smaller, right if larger, and you reach any node in O(h) time — O(log n) when the tree is balanced. It also makes validation a range problem: pass down a (low, high) window and check each node lies inside it. A tree that violates the property at any node is not a BST, however sorted its inorder looks locally.

4. Depth, diameter, and lowest common ancestors

▶ YouTube reference — the video for this lesson

Most tree interview problems are one recursive helper returning information upward. Diameter is the longest path through a node, computed from the depths of its children, with the answer tracked globally. Lowest common ancestor in a BST is a walk: if both targets are smaller, go left; if both larger, go right; otherwise this node is the split point. The pattern is always the same — define what the helper returns, handle the null base case, and combine children.

def invert(root):
    if not root:
        return None
    root.left, root.right = invert(root.right), invert(root.left)
    return root

Why does inorder traversal of a BST give sorted values?

Inorder visits left subtree, then node, then right subtree — and the BST property guarantees left values are smaller and right values larger, so the visit order is ascending.

How is tree diameter different from tree height?

Height is the longest downward path from a node; diameter is the longest path between any two nodes, which may pass through a node via both its children.

7 · Interview ▾

How do you validate a BST in one pass?

Recurse with a (low, high) range: each node must lie strictly inside it, and children get narrowed ranges — left child capped by the node, right child floored by it.

When is a BST search O(n) instead of O(log n)?

When the tree is unbalanced, like a chain from inserting sorted values — height becomes n. A balanced tree, or a self-balancing one, keeps height at log n.
