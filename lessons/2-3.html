1. A class bundles data with the behaviour that owns it

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

__init__ sets up the object's state; self is the object itself, passed explicitly. Methods are functions that live on the class and operate on that state.

2. The honest rules of OOP

▶ YouTube reference — the video for this lesson

  • Encapsulation: keep state and its rules together — a Progress class that refuses negative XP beats checks scattered across files.
  • Inheritance: an Exercise is-a Question can share behaviour — but deep hierarchies become rigid. Prefer composition (an object holding other objects) for most real designs.
  • Dataclasses: for classes that are mostly data, @dataclass generates init/repr for you. Skillzify's flowchart nodes are a natural dataclass.

3. When NOT to use a class

▶ YouTube reference — the video for this lesson

A dict is fine for data that only gets read (like parsed JSON). A function is fine for a one-step transformation. Reach for a class when state + rules + lifetime travel together — a learner's progress, a flowchart builder mid-construction. Over-classing simple data is its own smell.

Interview angle"Explain OOP" answers that recite four pillars fail. The answer that lands: a modelling example, one trade-off (inheritance vs composition), and one case where you deliberately didn't use a class.
Watch out — common mistakes
  • Deep inheritance trees for tiny scripts — classes where a dict would do.
  • Making every attribute public and then adding getter/setter ceremony anyway.

Composition vs inheritance — which do you reach for first, and why?

Composition: objects holding other objects stay flexible and loosely coupled; deep inheritance hierarchies are rigid and hard to change.

When is a dict better than a class?

For read-only or pass-through data (e.g. parsed JSON) with no rules or behaviour to protect — a class adds ceremony without buying safety.

7 · Interview ▾

Composition vs inheritance?

Inheritance shares behaviour through is-a relationships but couples tightly; composition assembles behaviour from parts and stays flexible — prefer it by default.

What does @dataclass give you?

Generated __init__, __repr__ and equality for data-holding classes — the boilerplate written for you.
