Goal — by the end of this lessonBy the end you can run a small project's security posture like a professional — secrets hygiene, a SECURITY.md with private reporting, dependency awareness — and read basic analytics without fooling yourself.

1. Secrets hygiene, the full doctrine

▶ YouTube reference — the video for this lesson

  • Keys live in env vars / platform secret stores — never in code, never in git history (history is forever; rotate any key that ever lands there).
  • .env is gitignored; .env.example with placeholder names is committed so teammates know what to set.
  • The Firebase web config is the famous exception that proves the rule: public by design, protected by rules (Lesson 4.4) — know which keys are which kind.

2. SECURITY.md and private reporting

▶ YouTube reference — the video for this lesson

Skillzify ships a SECURITY.md naming a security contact (the product email) and enables GitHub's private vulnerability reporting — researchers get a confidential channel instead of a public issue. Add Dependabot alerts and CodeQL from Lesson 8.2 and a one-person project has a genuinely professional posture: prevention (rules, validation), detection (scanning), and response (a published contact).

3. Analytics without self-deception

▶ YouTube reference — the video for this lesson

GA4 (Skillzify's G-YYR4JD16G8 on all pages) answers: which pages, from where, in what order, dropping off where. Read it for decisions — a lesson everyone abandons at minute one is a content bug. But respect its limits: small numbers are noise, pageviews aren't learning, and tracking must stay proportionate — measure the product, don't surveil the learner.

A Gemini key was committed to git last month but the file was later deleted. Safe?

No — git history retains it. The key must be rotated/revoked; deletion from the working tree does not purge history.

What three layers make up a small project's security posture?

Prevention (validation, rules, secrets hygiene), detection (CodeQL, Dependabot alerts), and response (SECURITY.md with private reporting channel).

7 · Interview ▾

How do you handle secrets in a project, end to end?

Env vars/secret stores only, .env gitignored with a committed .env.example, rotation on any suspected exposure, public-by-design configs (Firebase web) distinguished from true secrets and protected by rules.

What would you look at first in analytics for a learning product?

Per-lesson drop-off and completion funnels — where learners abandon is where the content or UX is broken; raw pageviews alone say almost nothing.
