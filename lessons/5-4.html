Structured Output & Streaming

Goal — by the end of this lessonBy the end you can force Gemini to return valid JSON matching a schema, stream a response token by token to the UI, and handle the partial-JSON problem that streaming creates.

1. Structured output: a contract, not a hope

▶ YouTube reference — the video for this lesson

Asking a model to reply in JSON with a polite instruction works until it does not — one day it adds a chatty sentence before the brace and your JSON.parse throws. Structured output turns the format into a contract: you declare a response schema, set the MIME type to JSON, and the model is constrained to produce only valid JSON matching that schema. Skillzify's quiz generator uses this to get exactly three questions, each with four options and one correct index — fields the frontend can render without defensive parsing gymnastics.

2. Streaming: show work as it arrives

▶ YouTube reference — the video for this lesson

A normal API call waits for the full reply, which can take seconds of dead silence. Streaming returns the response in chunks as tokens are generated, so the UI can render words as they appear — the typing effect users expect from AI chat. Under the hood it is server-sent events: the server forwards chunks, the client appends them. The cost is complexity: your UI now has three states — streaming, done, and failed halfway — and each needs handling.

3. The partial-JSON problem

▶ YouTube reference — the video for this lesson

Streaming and structured output collide: while streaming, the JSON is incomplete, so you cannot parse it until the final chunk. The standard solution is to stream the raw text for display and parse only the completed string, or to design the schema so each field can render progressively. Never render a half-parsed object as if it were final — a question with two options and no answer key is worse than a loading spinner.

▸ Code example — see the Code section below.

Streaming uses generateContentStream and iterates the stream, appending each chunk's text. Same schema, same guarantee — only the delivery changes.

4 · Code ▾

▶ Run works for JavaScript snippets below — it runs in a sandboxed worker with a 2-second timeout. Python, HTML and CSS snippets are read-only here.

// Structured output: schema-enforced JSON from Gemini
const result = await model.generateContent({
  contents: [{ role: "user", parts: [{ text: quizPrompt }] }],
  generationConfig: {
    responseMimeType: "application/json",
    responseSchema: {
      type: "OBJECT",
      properties: {
        question: { type: "STRING" },
        options: { type: "ARRAY", items: { type: "STRING" } },
        answerIndex: { type: "INTEGER" }
      },
      required: ["question", "options", "answerIndex"]
    }
  }
});
const quiz = JSON.parse(result.response.text()); // guaranteed valid JSON

Why is a response schema better than asking for JSON in the prompt text?

The schema constrains generation itself, so the output is guaranteed valid JSON in the declared shape. A prompt instruction is a suggestion the model can ignore or decorate.

Why can you not parse streamed JSON until the stream finishes?

Mid-stream the JSON is incomplete and invalid. You stream raw text for display and parse only the completed string.

7 · Interview ▾

When would you choose streaming over a single response?

For long, user-facing text where perceived latency matters — chat, explanations — because first tokens arrive in under a second. For machine-consumed JSON, a single call is simpler.

How do you handle a streamed response that fails halfway?

Keep the partial text visible with a clear incomplete state, offer retry, and never persist or act on the partial structured result as if it were complete.
