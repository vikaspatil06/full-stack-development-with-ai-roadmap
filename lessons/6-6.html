Goal — by the end of this lessonBy the end you can write Mermaid diagrams with subgraphs and custom styles, make nodes clickable, handle render errors gracefully, and choose the right diagram type for the idea.

1. Subgraphs group ideas, styles direct the eye

▶ YouTube reference — the video for this lesson

A flat flowchart of twenty nodes is unreadable; subgraphs fix that by grouping related nodes into labelled boxes — input, processing, output — so the reader sees structure before detail. Styling goes further: class definitions colour nodes by role, so decision points, errors and success paths are recognisable at a glance. Skillzify's flowchart generator emits subgraphs for function boundaries and colours error paths differently, which is why generated diagrams stay readable as programs grow.

2. Diagrams can be interactive

▶ YouTube reference — the video for this lesson

Mermaid nodes support click bindings: a node can link to a URL or trigger a callback. In Skillzify that means a flowchart node can jump to the lesson that explains the concept it represents — the diagram becomes navigation, not just a picture. Direction matters too: top-to-bottom suits processes, left-to-right suits timelines, and switching direction is one word in the diagram source. When a diagram renders badly, the fix is usually direction or grouping, not more nodes.

3. Render failures are a product problem

▶ YouTube reference — the video for this lesson

Mermaid parses a text syntax, and invalid syntax fails at render time — in front of the user. Never let a render error become a blank page: catch the failure, show the offending line, and keep the source visible so it can be fixed. Security level matters as well: Mermaid's default settings can execute embedded interaction, so Skillzify renders with a strict security level and sanitises generated source before it ever reaches the renderer.

When should you use subgraphs instead of adding more nodes to a flat diagram?

When nodes form natural groups — input, processing, output — so the reader sees structure before detail and the diagram stays readable at twenty-plus nodes.

Why must Mermaid render errors be caught and shown, not left blank?

A blank page hides the problem. Showing the error and the source lets the user fix the one broken line instead of guessing.

6 · Interview

Flowchart, sequence diagram, class diagram — how do you choose?

By what you need to show: control flow, interaction over time, or static structure. The idea picks the diagram, not the other way round.

Why does rendering user-generated Mermaid need a strict security level?

Mermaid can bind interactions from diagram source, so untrusted source could inject behaviour. Strict mode and sanitisation keep diagrams pictures, not code.
