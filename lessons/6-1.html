1. WebAssembly: a second language for the web

▶ YouTube reference — the video for this lesson

Browsers run JavaScript — and, since WASM, a compact binary format that other languages can compile to. Programs written in C, Rust or Python's C implementation can be compiled once to WASM and run in a tab at near-native speed, sandboxed like JavaScript.

2. Pyodide: CPython compiled to WASM

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

Skillzify's compiler page loads Pyodide v0.23.4 from the jsDelivr CDN; the learner's code runs entirely on their device. No server cost per run, works offline once loaded, and learner code never leaves the machine. The price: a heavy first load (the Python runtime is megabytes), so the compiler page loads it lazily and shows progress — and the homepage never pays that cost at all.

3. The honest comparison: browser vs server execution

▶ YouTube reference — the video for this lesson

  • Browser (Pyodide): free per-run, private, instant after load; but limited libraries, device-speed dependent, big initial download.
  • Server: full environment and libraries; but you pay per run, must sandbox hostile code seriously, and add network latency.

For teaching Python basics to learners on phones, Skillzify's choice is right. For data-science workloads, it wouldn't be.

Error plumbing mattersCapturing stdout and tracebacks from Pyodide and rendering them readably — plus the "Stuck?" button that sends editor state to the AI hint flow — is where this page stops being a demo and becomes a product.

What exactly is Pyodide?

The CPython interpreter compiled to WebAssembly, plus packaging to load it in a browser — real Python running client-side.

Why doesn't Skillzify put Pyodide on every page?

Its runtime is megabytes of download; only the compiler page needs it. Loading it everywhere would tax every visit for one page's feature.

7 · Interview ▾

How does your in-browser Python compiler work?

Pyodide — CPython compiled to WebAssembly — loads from a CDN on the compiler page; learner code executes locally in the tab, with stdout/errors captured and rendered, and no server involved per run.

Client-side vs server-side code execution — trade-offs?

Client: zero marginal cost, privacy, offline; heavy load, limited environment. Server: full environment; per-run cost, serious sandboxing duty, latency.
