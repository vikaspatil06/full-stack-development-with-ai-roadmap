Greedy Algorithms

Take the best now — when now is enough

1. The greedy idea: local best, global best

▶ YouTube reference — the video for this lesson

A greedy algorithm makes the choice that looks best right now and never revisits it. When it works, it is unbeatable: simple, fast, usually O(n log n) for the sort plus a linear scan. Assign Cookies is the purest form — sort children by greed and cookies by size, then give each child the smallest cookie that satisfies them. The whole risk of greedy is in one question: does the locally best choice ever ruin the global answer? If you cannot argue why it does not, you do not have a solution yet — you have a hope.

2. The exchange argument: how greedy is proven

▶ YouTube reference — the video for this lesson

The standard proof is the exchange argument. Take an optimal solution that differs from the greedy one at the first choice, and show you can swap the optimal choice for the greedy choice without making the solution worse. If the swap always works, greedy is optimal. For interval scheduling — maximum number of non-overlapping meetings — the greedy choice is the interval that ends earliest: swapping any optimal first interval for the earliest-ending one leaves at least as much room for everything after, so the swap never hurts. That one sentence is the entire proof, and being able to say it is what separates greedy from guessing.

3. Interval scheduling and its family

▶ YouTube reference — the video for this lesson

Sort intervals by end time, take the first, then repeatedly take the next interval that starts at or after the last taken one ends. The same skeleton solves Minimum Number of Arrows to Burst Balloons (sort by end, shoot at the end, skip everything the arrow bursts) and Non-overlapping Intervals (count removals instead of keeps). Jump Game is greedy in another costume: track the farthest reachable index, and if the current index ever exceeds it, the end is unreachable. In every case the pattern is sort or scan, one pass, one irrevocable choice at a time.

4. When greedy fails: the coin-change counterexample

▶ YouTube reference — the video for this lesson

Greedy fails when a locally best choice blocks a better global combination. Coin change with denominations 1, 3 and 4 and a target of 6 is the classic trap: greedy takes 4, then needs two 1s — three coins — while 3 plus 3 uses two. Real currency systems are designed so greedy works; arbitrary denominations are not, and the correct tool becomes dynamic programming. The interview habit is to hunt for a small counterexample before committing to greedy: try to break your own algorithm with tiny inputs, and only trust it when you cannot.

def max_meetings(intervals):
    intervals.sort(key=lambda x: x[1])
    count = 0
    last_end = float("-inf")
    for start, end in intervals:
        if start >= last_end:
            count += 1
            last_end = end
    return count

# Earliest end first: each pick leaves maximal room. O(n log n) for the sort.

Why does earliest-end-first work for interval scheduling?

The interval ending earliest leaves at least as much room for all later intervals as any other first choice, so swapping it into an optimal solution never makes that solution worse.

What is an exchange argument?

A proof that an optimal solution can be transformed into the greedy one, choice by choice, without getting worse — establishing that greedy is optimal.

Give a counterexample where greedy coin change fails.

Denominations 1, 3, 4 with target 6: greedy uses 4+1+1 (three coins) while 3+3 uses two. Arbitrary coin systems need dynamic programming instead.

How does Jump Game use a greedy invariant?

It tracks the farthest index reachable so far; if the scan ever reaches an index beyond that, the end is unreachable, otherwise it is reachable.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “Greedy algorithm”?

An algorithm that makes the locally best choice at each step and never revisits it — optimal only when the choice is provably safe.

What is “Exchange argument”?

The standard greedy proof: swap the greedy choice into an optimal solution without making it worse, repeatedly, until they match.

What is “Interval scheduling”?

Selecting the maximum set of non-overlapping intervals by always taking the one that ends earliest.

What is “Greedy choice property”?

The property that a locally optimal choice belongs to some globally optimal solution — the precondition for greedy to work.

What is “Counterexample”?

A small input that breaks an algorithm; hunting for one is how you test a greedy idea before trusting it.

What is “Farthest-reach invariant”?

The Jump Game greedy state: the maximum index reachable so far, updated in one pass.

7 · Interview ▾

How do you decide whether a problem is greedy or DP?

Try to prove the greedy choice safe with an exchange argument, and hunt for a small counterexample. If a counterexample exists or the proof will not close, the problem needs DP.

Explain why sorting by end time, not start time, is right for interval scheduling.

Earliest start can be a long interval that blocks many others. Earliest end guarantees the most remaining room, which is exactly what the exchange argument needs.
