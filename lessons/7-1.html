2. Null safety: the type system refuses the classic crash

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

In Java, any reference might be null and you find out in production. In Kotlin, nullable types are explicit, and the compiler forces you to handle them. For an app reading Firestore documents — where any field might be missing — this eliminates an entire crash category, provided you resist the !! "trust me" operator.

3. Where Kotlin differs in spirit

▶ YouTube reference — the video for this lesson

Everything is an object (no primitives at the language level), functions are first-class, and immutability (val) is the cultural default — the same "don't mutate" discipline from Lesson 1.1, enforced by the language.

What problem does Kotlin's String? vs String distinction solve?

Nullability is explicit in the type and checked by the compiler, so missing-value crashes (Java's NPE epidemic) become compile-time obligations instead of production surprises.

What does the Elvis operator ?: do?

It supplies a default value when the left side is null: nickname?.length ?: 0 means 'length, or 0 if nickname is null'.

7 · Interview ▾

Why does Android's move from Java to Kotlin matter in practice?

Null safety removes a top crash class, data classes and lambdas cut boilerplate, and coroutines simplify async — all of which show up daily in production Android code quality.

val vs var — and why default to val?

val is read-only (like const), var is mutable. Defaulting to val makes state changes deliberate and code easier to reason about.
