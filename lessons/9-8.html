Frontend and backend in one project

1. File-based routing: folders are URLs

▶ YouTube reference — the video for this lesson

In Next.js the app folder is the route map. A page.tsx file inside app/lessons becomes the /lessons page, a nested folder becomes a nested path, and a folder named [id] becomes a dynamic segment that matches any lesson id. Layouts wrap their children, so the shared navigation is written once instead of pasted into every page. Skillzify achieves the same sharing by injecting its nav with JavaScript on each static page; Next.js makes it structural.

2. Server components versus client components

▶ YouTube reference — the video for this lesson

By default, components in the app router render on the server: they can read databases and secrets directly, ship no JavaScript to the browser, and stream HTML quickly. A component that needs interactivity — clicks, state, browser APIs — opts in with the "use client" directive and renders in the browser. The discipline is to keep client components small and leaf-like: a static lesson page rendered on the server, with one small client component for the interactive quiz. Every client component adds to the JavaScript bundle, so the split is also a performance decision.

3. Route handlers and data fetching

▶ YouTube reference — the video for this lesson

A route.ts file inside app/api is a backend endpoint: export a GET or POST function and Next.js serves it. Server components fetch data directly with await — no effect hooks, no loading spinners for the first paint — and can cache or revalidate that data declaratively. This collapses the classic two-project setup, a React frontend plus an Express API, into one codebase with one deploy.

4. When Next beats a separate Express backend

▶ YouTube reference — the video for this lesson

Next.js wins when the frontend and backend are built by the same team, deployed together, and the API mostly serves the pages — exactly the shape of most product sites, and the shape Skillzify would have if it were rebuilt in React. A separate Express backend still wins when the API serves many clients (web, Android, third parties), needs long-running processes or WebSockets, or must scale independently of page traffic. The honest test: if your API exists only to feed your own pages, one project is simpler; if it is a product in itself, keep it separate.

// app/api/lessons/route.ts — a route handler
import { NextResponse } from "next/server";

const lessons = [{ id: "b-1", title: "Intro", xp: 20 }];

export async function GET() {
  return NextResponse.json(lessons);
}

export async function POST(req: Request) {
  const body = await req.json();
  if (!body.title) {
    return NextResponse.json({ error: "title required" }, { status: 400 });
  }
  lessons.push({ id: "b-" + (lessons.length + 1), title: body.title, xp: 20 });
  return NextResponse.json({ ok: true }, { status: 201 });
}

How does file-based routing map folders to URLs?

Each folder under app is a path segment and a page file inside it renders that route; a [id] folder matches any value as a dynamic parameter.

What can a server component do that a client component cannot?

It can access databases, files and secrets directly on the server and ships no JavaScript to the browser. Client components are for interactivity and browser APIs.

Why keep client components small and leaf-like?

Every client component adds JavaScript to the bundle. Small leaves keep pages fast while still allowing interaction where it is needed.

When is a separate Express backend still the better choice?

When the API serves multiple clients, needs long-running or WebSocket workloads, or must scale independently of the frontend.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “File-based routing”?

Routes defined by folders and page files under app, instead of a central route configuration.

What is “Dynamic segment”?

A folder like [id] that matches any value in that position and exposes it as a parameter.

What is “Server component”?

A component rendered on the server that can access data and secrets directly and ships no client JavaScript.

What is “Client component”?

A component marked use client that renders in the browser and can use state, effects and browser APIs.

What is “Route handler”?

A route.ts file exporting GET, POST and similar functions — a backend endpoint inside the Next.js project.

What is “Layout”?

A component wrapping a route segment and its children, so shared chrome like navigation is written once.

7 · Interview ▾

Explain server versus client components in one minute.

Server components render on the server, can read data and secrets directly, and send no JavaScript to the browser. Client components, marked use client, run in the browser for state and events. You compose them: server pages with small client leaves.

How does data fetching differ in Next.js from plain React?

Server components fetch with plain await during rendering, so the first paint already has data — no effect hook, no client waterfall. Caching and revalidation are declared per fetch instead of hand-managed.
