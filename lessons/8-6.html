Goal — by the end of this lessonBy the end you can compare static hosting, a managed service like Render, and raw cloud (AWS) — and explain Skillzify's actual deploy topology, including its manual-redeploy quirk.

1. Three models, three bargains

▶ YouTube reference — the video for this lesson

  • Static hosting (GitHub Pages): files only, no server code. Free, instant, perfect for the frontend — useless for /api routes and secrets. Skillzify mirrors its static site here.
  • Managed service (Render): runs your Node server from a repo + render.yaml: build command npm install, start npm start, env vars in a dashboard. Free tier sleeps when idle (cold starts) — the price of free.
  • Cloud (AWS): raw building blocks — S3 stores files, EC2 rents computers, IAM controls who may do what. Maximum control, maximum responsibility. Skillzify does not use AWS; you learn it because employers do.

2. Skillzify's real topology

▶ YouTube reference — the video for this lesson

Production and staging are separate Render services from the same repo, differing only in env vars. Because staging was connected by public repo URL (not the GitHub App), pushes do not auto-deploy — redeploy is a manual dashboard action. Forgetting this once teaches the lesson forever: "I pushed the fix" ≠ "the fix is live". Verify the deployed thing, not the repo.

3. Environments and configuration

▶ YouTube reference — the video for this lesson

Code should be identical across environments; configuration (env vars: keys, caps, model names) differs. The moment staging and production run different code, staging stops predicting production — the entire point of having it.

AWS literacy checklist (concepts only)S3 = object storage, EC2 = virtual servers, IAM = permissions, Region = geography of your infrastructure. Be able to place each in a sentence about a real architecture; deep AWS is its own certification track, not this roadmap's job.

Why doesn't Skillzify's staging update when code is pushed?

It was connected via public repo URL without the GitHub App integration, so no deploy webhook fires — redeploys are triggered manually from the Render dashboard.

Staging and production must run identical what, and differ in what?

Identical code; different configuration via environment variables (keys, caps, endpoints).

7 · Interview ▾

Static hosting vs a server host — how do you choose per part of an app?

Static for files (fast, free, cacheable); a server host wherever secrets, dynamic APIs or per-user logic live. Skillzify uses both: Pages mirror + Render service.

Explain S3, EC2 and IAM in one breath.

S3 stores objects/files, EC2 provides virtual compute, IAM defines who and what can access both.
