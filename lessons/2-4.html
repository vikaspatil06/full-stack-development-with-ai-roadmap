OOP Inheritance & Polymorphism — Sharing Behaviour Safely

Is-a relationships without the spaghetti

Goal — by the end of this lessonBy the end you can design a class hierarchy with inheritance, override methods polymorphically, and know when composition beats inheritance.

1. Inheritance shares behaviour

▶ YouTube reference — the video for this lesson

A subclass inherits the methods and attributes of its parent, then adds or overrides what is specific. A QuizExercise and a CodeExercise can both inherit from Exercise, sharing scoring and timing while each implements its own render method. Inheritance models a genuine is-a relationship: a quiz exercise is an exercise.

2. Polymorphism: one call, many behaviours

▶ YouTube reference — the video for this lesson

Polymorphism means calling the same method on different objects and getting each object's own behaviour. A loop over exercises calling render works for every subclass without knowing which type it holds. Duck typing takes this further in Python: if it has the method, it can be used — no shared parent required.

▸ Code example — see the Code section below.

3. super and method resolution

▶ YouTube reference — the video for this lesson

super() calls the parent's version of a method, so a subclass can extend behaviour instead of replacing it. Python resolves methods along the method resolution order, which matters in multiple inheritance — keep hierarchies shallow so the order never becomes a puzzle.

4. Composition over inheritance

▶ YouTube reference — the video for this lesson

Deep inheritance trees become rigid: changing a parent ripples everywhere. Composition assembles behaviour from parts — an exercise has a scorer and a renderer — and stays flexible. Prefer inheritance for a true is-a relationship with shared behaviour, composition for everything else. A practical test is the sentence check: if you cannot say a QuizExercise is an Exercise in plain English, inheritance is the wrong tool and composition is the better design.

3 · Code

class Exercise:
    def __init__(self, title):
        self.title = title
    def render(self):
        return "Exercise: " + self.title

class QuizExercise(Exercise):
    def render(self):
        return "Quiz: " + self.title + " [4 options]"

for ex in [Exercise("Loops"), QuizExercise("Arrays")]:
    print(ex.render())

What is polymorphism, in the context of the code above?

Calling render on different exercise objects produces each class's own output through one shared interface — the caller never checks the type.

Why is composition often preferred over deep inheritance?

Inheritance couples subclasses tightly to parents, so changes ripple; composition assembles behaviour from parts that can be swapped independently.

6 · Interview

Inheritance vs composition — when each?

Inheritance for a genuine is-a relationship with shared behaviour; composition by default, because it stays flexible and avoids fragile base-class problems.

What does super() do in Python?

It calls the parent class's version of a method, letting a subclass extend behaviour instead of fully replacing it.
