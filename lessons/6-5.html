2. Skillzify's three-stage pipeline

▶ YouTube reference — the video for this lesson

Recall Module 2: flowchart-gen.py parses Python code into a JSON list of nodes and edges. A thin converter turns that JSON into Mermaid syntax, and Mermaid 10 renders the SVG in compiler.html / lesson pages. Each stage has one job: Python decides structure, JSON carries it, Mermaid draws it. Swap the renderer tomorrow and the generators don't change.

3. When text-diagrams are the wrong tool

▶ YouTube reference — the video for this lesson

Precise spatial layouts, dense architecture posters, anything needing pixel control — text diagramming fights you. For algorithmic flowcharts generated from learner code, it's exactly right.

The reusable ideaIntermediate representations (here: JSON) between a producer and a renderer are one of software's deepest patterns — compilers do it (AST → IR → machine code), and so does this little flowchart feature.

Why is generating Mermaid text better than generating a flowchart image directly?

Text is generatable, storable, diffable and renderer-independent; an image pipeline locks you into one drawing implementation and opaque output.

Name the three stages of Skillzify's flowchart pipeline and each stage's job.

Python generators decide structure → JSON carries nodes/edges → Mermaid renders the diagram.

6 · Interview

Why introduce an intermediate JSON format between your parser and renderer?

Decoupling: either side can change independently, the format is testable on its own, and other renderers can consume the same data later.

Advantage of diagrams-as-text in a team workflow?

They live in git, diff in pull requests, and can be generated from code — reviews cover diagrams like any other source.
