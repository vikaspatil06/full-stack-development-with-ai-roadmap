1. Embeddings turn meaning into geometry

▶ YouTube reference — the video for this lesson

An embedding is a list of numbers — a vector — produced from a piece of text, positioned so that similar meanings sit close together. Cosine similarity measures the angle between two vectors: near 1 means near-identical meaning, near 0 means unrelated. A vector database stores these embeddings alongside the original text and answers one question fast: given this query vector, which stored vectors are closest? That is the retrieval half of RAG, and it is how a tutor can find the three most relevant lesson passages for a question instead of pasting the whole course into the prompt.

2. Chunking decides retrieval quality

▶ YouTube reference — the video for this lesson

You do not embed whole lessons. You split them into chunks — a section, a paragraph, a concept — because a query matches a focused chunk far more precisely than a long document that mentions everything. Too small and the chunk lacks context; too large and it dilutes the match. Overlap the chunks slightly so an idea split across a boundary is still retrievable, and store metadata — lesson ID, section — so the retrieved text can link back to its source instead of floating as an uncited claim.

3. Prompt caching: pay once for repeated context

▶ YouTube reference — the video for this lesson

Many calls share the same long prefix — the system prompt, the course outline, the retrieved passages. Prompt caching stores that prefix server-side and charges a fraction for reusing it instead of reprocessing it every time. Gemini's context caching works the same way: cache the stable context, send only the new question per call. The saving is real money at volume, and the design rule is simple — keep the stable part stable and put the changing part last.

Retrieval quality is the product's quality: bad chunks mean confident answers from the wrong passage, so evaluate retrieval separately from generation.

What does cosine similarity measure between two embedding vectors?

The angle between them: near 1 means the texts are semantically close, near 0 means unrelated — it is the ranking signal for retrieval.

Why chunk documents instead of embedding whole lessons?

A focused chunk matches a query precisely; a whole lesson dilutes the match and returns vague context. Chunks also keep retrieved context small and cheap.

7 · Interview ▾

RAG vs fine-tuning vs a long prompt — when is each right?

RAG for knowledge that changes or must be cited; fine-tuning for stable style or behaviour; long prompts only for small, one-off context.

How do you know your retrieval is bad before users complain?

Evaluate it separately: a test set of questions with known-correct source chunks, measuring whether the right chunk is in the top results.
