One pass, two indices, zero extra space

1. Arrays are contiguous memory

▶ YouTube reference — the video for this lesson

An array stores elements side by side, so indexing is O(1) — the address is just base plus index times element size. The price is that inserting or deleting in the middle shifts everything after it, costing O(n). That single fact drives most array design: read-heavy, index-heavy work loves arrays, while frequent middle insertions want a linked list instead. In interviews, assume the array is the default structure and ask whether sorting it first unlocks a cheaper pattern.

2. The two-pointer pattern

▶ YouTube reference — the video for this lesson

Two pointers turn many O(n²) pair problems into O(n). The opposite-ends variant works on sorted input: one pointer at each end, moving inward based on whether the current sum is too small or too large. The same-direction variant has a slow pointer marking the boundary of the processed region and a fast pointer scanning ahead — the shape of every remove-duplicates problem. The recognition cue is a pair or a partition; the precondition is usually sorted input, so sorting is often step one.

3. Prefix sums and the one-pass mindset

▶ YouTube reference — the video for this lesson

A prefix-sum array answers any range-sum query in O(1) after one O(n) pass, and the running-sum variant answers subarray problems without storing anything extra. Kadane's algorithm is the same idea for maximum subarray: carry the best sum ending here, reset it when it goes negative. Whenever a brute force recomputes a sum or a scan from scratch inside a loop, ask what running value would make that work free.

4. Off-by-one errors and bounds

▶ YouTube reference — the video for this lesson

Most array failures are boundary failures: a loop that runs one step too far, a pointer that crosses its partner, or a window that never shrinks. Defend yourself with invariants: state out loud what each pointer means before the loop, and test the empty array, the single element, and the all-equal array. If your loop condition is while left < right, know exactly what equality means for your answer, and trace two tiny examples by hand before trusting it.

def two_sum_sorted(nums, target):
    left, right = 0, len(nums) - 1
    while left < right:
        total = nums[left] + nums[right]
        if total == target:
            return [left + 1, right + 1]
        if total < target:
            left += 1
        else:
            right -= 1
    return []

# Sorted input lets two pointers find the pair in O(n), O(1) space.

When does the opposite-ends two-pointer pattern apply?

When the input is sorted and you need a pair satisfying a condition — the pointers move inward based on whether the current pair is too small or too large.

Why is Kadane's algorithm O(n) instead of O(n²)?

It carries the best subarray sum ending at the current index forward, resetting when negative, so each element is processed once instead of restarting a scan at every index.

7 · Interview ▾

You sorted the array to use two pointers, but the problem asks for original indices. What now?

Keep the original indices alongside the values — sort pairs of (value, index) — or use a hash map, which preserves indices at the cost of O(n) extra space.

How do you avoid off-by-one errors in two-pointer code?

State the invariant for each pointer before the loop, decide what left == right means, and trace the empty, single-element and two-element cases by hand.
