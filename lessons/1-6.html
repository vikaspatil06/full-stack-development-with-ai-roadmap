DOM Events & Delegation — Listening Smart

Bubbling, capturing, and one listener for a thousand elements

Goal — by the end of this lessonBy the end you can explain event bubbling, use delegation to handle dynamic lists with a single listener, and stop memory leaks from orphaned listeners.

1. Events travel in three phases

▶ YouTube reference — the video for this lesson

When a user clicks a button inside a card inside a page, the event travels down from the window to the target (capturing), fires at the target, then bubbles back up through every ancestor. addEventListener listens on the bubbling phase by default. Understanding this journey is the key to everything else in this lesson, because it means ancestors can hear events from descendants.

2. Delegation: one listener, endless children

▶ YouTube reference — the video for this lesson

Instead of attaching a listener to every lesson card, attach one to their shared parent and check event.target to see which child was actually clicked. New cards added later work automatically, because the parent was already listening. Skillzify's Learn page renders 250 lessons from data — delegation is the only sane way to wire them all.

▸ Code example — see the Code section below.

3. Controlling the flow

▶ YouTube reference — the video for this lesson

stopPropagation halts the journey so ancestors never hear the event; preventDefault stops the browser's default action, like following a link or submitting a form. Use both sparingly — stopping propagation can break other features listening higher up, and preventing defaults on the wrong element breaks accessibility.

4. Listeners and memory

▶ YouTube reference — the video for this lesson

Every listener holds a reference to its element. Remove an element without removing its listeners and the memory can linger. Delegation avoids this almost entirely: one listener on a long-lived parent, no per-item cleanup, and dynamic content that just works.

document.getElementById("lessonList").addEventListener("click", function (e) {
  const card = e.target.closest(".lesson-card");
  if (!card) return;               // click was not on a card
  openLesson(card.dataset.id);     // one listener serves all cards
});

Why does event delegation work for elements added after the listener was attached?

The listener lives on the parent, and events from new children still bubble up to it — the parent never needed to know the children existed.

What does e.target.closest do, and why is it useful here?

It walks up from the clicked element to the nearest ancestor matching the selector, so clicks on a card's inner text or icon still resolve to the card.

7 · Interview ▾

Explain event bubbling and capturing.

Capturing travels from window down to the target; bubbling travels back up through ancestors. Listeners default to bubbling.

When would you use stopPropagation, and what is the risk?

To keep an event from reaching ancestors, e.g. a button inside a card. The risk is silently breaking other features that listen higher up.
