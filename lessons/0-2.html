1. DNS: names to numbers

▶ YouTube reference — the video for this lesson

Computers talk to IP addresses, humans use names. DNS is the lookup system that turns skillzify-v2-staging.onrender.com into an IP. The browser checks its cache, then the OS cache, then asks a resolver, which walks from the root servers down to the authoritative server for the domain. A slow first visit is often DNS, not your code — and caching at each level is why repeat visits are fast.

2. HTTP requests and responses

▶ YouTube reference — the video for this lesson

Every web interaction is a request with a method, a path, headers and an optional body, answered by a response with a status code, headers and a body. GET reads, POST creates, PUT and PATCH update, DELETE removes. Headers carry metadata: Content-Type says the body is JSON, Authorization carries a token, Cache-Control says how long to keep a copy.

▸ Code example — see the Code section below.

3. Status codes are a language

▶ YouTube reference — the video for this lesson

2xx means success, 3xx means redirect, 4xx means the client made a mistake (400 bad input, 401 unauthenticated, 403 forbidden, 404 not found, 429 too many requests), and 5xx means the server failed. Skillzify's API returns 429 when the rate limit fires and 400 when the question is empty — the frontend reads the code and shows the right message instead of guessing.

4. Debugging in the Network tab

▶ YouTube reference — the video for this lesson

Open DevTools, click Network, reload, and every request appears with its status, size and timing. Click one to see its headers and body. When a feature breaks, this tab tells you in seconds whether the problem is the request, the response, or the code that renders it.

What is the difference between a 401 and a 403?

401 means unauthenticated — no valid credentials were presented. 403 means authenticated but forbidden — the identity is known and still not allowed.

Why does fetch not reject on a 500 response?

fetch only rejects on network-level failures. An HTTP error status still resolves, so code must check res.ok or res.status itself.

6 · Interview

Walk me through DNS resolution for a URL you type.

Browser cache, then OS cache, then the resolver queries root, TLD and authoritative servers, returning the IP; the result is cached at each level.

What does a 429 status code mean, and how should a client handle it?

Too many requests — the client hit a rate limit. It should back off, wait, and retry later, ideally respecting a Retry-After header.
