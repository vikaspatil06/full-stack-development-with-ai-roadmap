Function & Tool Calling

Give the model hands: declare tools, run them, return the result

1. The model does not run code — it asks you to

▶ YouTube reference — the video for this lesson

Tool calling is the most misunderstood LLM feature. The model never executes your function. It reads the tool declaration — name, description, parameters — decides the user's request needs that tool, and returns a structured function call: which function, with which arguments. Your code runs the function against the real world, then sends the result back to the model, which writes the final answer. The model is the brain that decides; your server is the hands that act.

2. The loop, step by step

▶ YouTube reference — the video for this lesson

One turn becomes a loop: send the prompt plus tool declarations; if the reply contains a function call, execute it and append the result as a function-response message; send the conversation back and repeat until the model answers in plain text. Skillzify's tutor could offer a getLessonProgress tool — the learner asks where they stand, the model calls the tool, your server reads Firestore, and the model turns the raw numbers into a human answer. The tool's description is its documentation to the model: vague descriptions produce wrong calls.

3. Trust boundaries matter

▶ YouTube reference — the video for this lesson

Tools that read are safe to expose broadly; tools that write need gates. A tool that marks a lesson complete or changes XP must validate the caller and the arguments server-side, because the model can be tricked by prompt injection in user input into calling tools with attacker-chosen arguments. Treat every function call like an API request from an untrusted client: validate, authorise, then execute.

▸ Code example — see the Code section below.

One declaration, one executor, one loop — that pattern scales from one tool to twenty, and it is the entire machinery behind AI agents.

Who actually executes a function the model calls?

Your server code. The model only returns a structured call request; you run the function and send the result back for the final answer.

Why do write tools need server-side validation even though the model chose the arguments?

Arguments can be influenced by prompt injection in user input, so every call must be validated and authorised like any untrusted API request.

7 · Interview ▾

Explain the tool-calling loop in one minute.

Declare tools with schemas, send prompt plus declarations, execute any returned function call, append the result, repeat until the model answers in text.

What makes a good tool description?

Precise purpose, when to use it, what each parameter means and its constraints — the description is the model's only documentation, so vagueness causes wrong calls.
