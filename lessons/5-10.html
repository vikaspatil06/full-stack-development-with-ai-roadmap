Goal — by the end of this lessonBy the end you can add basic guardrails around an AI feature and run a simple eval set that tells you — with numbers — whether a prompt or model change helped or hurt.

1. Guardrails: fences at the borders

▶ YouTube reference — the video for this lesson

  • Input side: length limits and validation (Module 3), block-list for obviously out-of-scope abuse, delimiters against injection (Lesson 5.3).
  • Output side: schema validation for JSON modes, a refusal/fallback path, and never executing model output as code or queries without a sandbox and review.
  • Product side: Skillzify's Socratic rule is a guardrail — the tutor must not hand over exercise solutions. Policy can live in prompts, but verify it with tests, because prompts leak.

2. Evals: a test suite for behaviour

▶ YouTube reference — the video for this lesson

Normal code gets unit tests; AI features get evals — a fixed set of inputs with expected properties:

▸ Code example — see the Code section below.

Run the set after every prompt/model change; score pass rates automatically where checks are mechanical (contains, length, JSON validity) and by quick human review where they're not. A change that lifts the pass rate from 82% to 91% is progress; one that drops it is a regression — regardless of how the new prompt feels.

3. The loop that makes AI products good

▶ YouTube reference — the video for this lesson

Ship → log real failures (with privacy care) → add the failures to the eval set → fix → re-run evals → ship. Your eval set grows from real usage, which is exactly why it stays representative.

Scope for this roadmapYou need the habit, not a platform: a JSON file of 15–20 cases and a script that runs them and reports a score. That's a portfolio-worthy eval rig for Skillzify's tutor.

5 · Check

Say your answer out loud first, then reveal. Mark “I knew it” for +5 XP each.

Why can't prompts alone be your guardrails?

Prompts are advisory to the model — injection and edge cases leak through. Enforce at the borders: input validation, output validation, and behavioural tests.

What makes an eval set trustworthy over time?

It's fixed (so scores are comparable across changes) and grows from real logged failures (so it stays representative of actual usage).

6 · Interview

How do you know a prompt change improved your AI feature?

A fixed eval set with mechanical and reviewed checks, run before and after: compare pass rates per category, inspect new failures, and only ship improvements.

Your tutor must never solve exercises for students. How do you guarantee it?

Defence in depth: Socratic rules in the system prompt, output checks for solution-shaped responses, trap cases in the eval set run on every prompt/model change, and a fallback hint response on violation.
