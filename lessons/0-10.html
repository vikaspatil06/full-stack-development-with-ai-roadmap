1. The core language, fast

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

Use const by default, let when reassignment is real, and treat var as legacy. Objects and arrays hold structured data; functions package behaviour; arrow functions are the compact form you'll see everywhere in modern code.

2. The DOM is JavaScript's handle on the page

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

querySelector finds elements, addEventListener reacts to clicks, keys and input, and properties like textContent and classList change what the user sees. Almost all frontend JavaScript is this loop: find → listen → change.

3. localStorage: the browser's tiny notebook

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

It stores strings only, per site, and survives reloads. Objects must go through JSON.stringify on the way in and JSON.parse on the way out. Skillzify wraps both in try/catch helpers (storeGet/storeSet) so one corrupted value can never crash a page.

4. app.js: four jobs, wrapped safely

▶ YouTube reference — the video for this lesson

app.js is wrapped in an IIFE — (function () { "use strict"; ... })(); — so its variables stay private instead of leaking into the global scope where other files could collide with them. Inside, it does four jobs on every page: applies the saved theme, wires the mobile nav toggle and current-page highlighting, provides toast(msg), and provides the storage helpers. It then deliberately exposes just those helpers as window.Skillzify.toast and friends for other files. Everything waits for DOMContentLoaded — touching elements before they exist is the classic beginner crash.

How Skillzify uses thisThe pre-paint theme script in the head reads skillzify_theme from localStorage before first paint — that's why dark-mode users never see a white flash. Same storage, used earlier, for a visual reason.
Watch out — common mistakes
  • Touching DOM elements before DOMContentLoaded — the classic null crash.
  • Storing objects in localStorage without JSON.stringify and reading back '[object Object]'.

Why does app.js wrap everything in an IIFE?

To keep its variables and helper functions out of the global scope, avoiding name collisions with the ~30 other JS files; it exposes only the intended API via window.Skillzify.

localStorage can only store strings — how does Skillzify store a progress object?

JSON.stringify when saving and JSON.parse when loading, wrapped in try/catch so bad data can't crash the page.

7 · Interview ▾

What is an IIFE and why use one in a multi-file vanilla app?

An immediately-invoked function expression that scopes variables privately, preventing global collisions across files; you expose only a deliberate API.

localStorage vs a real database — limits?

Strings only, ~5MB, synchronous, per-device and per-browser, no queries and no cross-device sync — fine for preferences and progress caches, not a data layer.
