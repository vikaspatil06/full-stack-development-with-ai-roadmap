AWS Basics — EC2, S3, Lambda & IAM

The four services everything else stands on

1. IAM: who can do what

▶ YouTube reference — the video for this lesson

IAM (Identity and Access Management) is AWS's permission system, and it comes first because everything else is gated by it. Users are people or applications with credentials; roles are identities that services assume temporarily, with no long-lived password; policies are JSON documents listing allowed actions on named resources. The governing principle is least privilege: grant exactly the actions needed, on exactly the resources needed, and nothing more. A policy that allows s3:GetObject on one bucket is safe; a policy that allows everything on everything is how breaches happen.

2. S3: object storage for files

▶ YouTube reference — the video for this lesson

S3 stores objects — files plus metadata — in buckets, addressed by a key like a path. It is not a filesystem and not a database: you put whole objects and get whole objects, and it scales to effectively unlimited size with very high durability. Static websites, uploaded images, backups and build artifacts all live in S3. Buckets are private by default, and making one public is a deliberate, per-object or per-policy decision. Skillzify's equivalent is Firebase Storage for user files and the GitHub repository itself for static assets.

3. EC2: rented virtual servers

▶ YouTube reference — the video for this lesson

EC2 gives you virtual machines — instances — in sizes from tiny to enormous, billed per second while they run. You choose the operating system image, the size, and the security group (a firewall rule set), then you own everything above the hypervisor: patching, scaling, backups. That control is the point and the cost. Skillzify runs on Render, which is the managed version of this idea: Render operates the machines and deploys your code, while EC2 hands you the machine and wishes you luck.

4. Lambda: functions without servers

▶ YouTube reference — the video for this lesson

Lambda runs a single function in response to an event — an HTTP request, a file landing in S3, a timer — and bills only for the milliseconds it runs. There is no server to patch or scale; AWS starts copies as needed and shuts them down when idle. The trade-offs are cold starts on the first invocation, a 15-minute maximum runtime, and statelessness between calls. Firebase Cloud Functions is the same model in Google's cloud. The mapping to remember: EC2 is a rented computer, Lambda is rented execution, S3 is rented storage, and IAM decides who may rent what.

What is the difference between an IAM user and an IAM role?

A user is a permanent identity with credentials. A role is a temporary identity that a person or service assumes, with credentials that expire — the safer choice for applications.

Why is S3 called object storage rather than a filesystem?

You store and retrieve whole objects by key; there are no folders, no partial edits and no file locking like a real filesystem.

When does Lambda beat EC2, and when does it lose?

Lambda wins for event-driven, spiky work with no idle cost. It loses for long-running processes, steady high load, and anything needing local state between calls.

What does least privilege mean in an IAM policy?

Grant only the specific actions on the specific resources that are needed, and nothing else — so a leaked credential can do minimal damage.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “IAM”?

AWS Identity and Access Management: users, roles and policies controlling who can do what to which resources.

What is “Least privilege”?

Granting only the actions and resources actually needed, so compromised credentials can do minimal damage.

What is “S3 bucket”?

A container for objects (files plus metadata) addressed by key, private by default, built for durability at any scale.

What is “EC2 instance”?

A rented virtual machine whose size, image and firewall you choose and whose software you maintain.

What is “Lambda”?

Serverless functions that run on events and bill per millisecond of execution, with no server to manage.

What is “Security group”?

A virtual firewall attached to an instance, controlling which traffic may reach it.

7 · Interview ▾

Explain the four core AWS services to a beginner in one minute.

IAM controls who can do what. S3 stores files as objects in buckets. EC2 rents virtual servers you manage. Lambda runs single functions on events with no server to manage. Everything else in AWS builds on these.

Your app stores user uploads and runs a small API. Which services do you pick?

S3 for the uploads with a least-privilege IAM role, and Lambda behind an API gateway for the API if traffic is spiky, or a small EC2 or managed container if it is steady — with the trade-off stated either way.
