2. State with useState, effects with useEffect

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

useState gives a component memory; calling the setter re-renders with the new value — you never touch the DOM directly. useEffect runs side effects (fetching, titles, subscriptions) after render, with a dependency array controlling when. Lists need a stable key per item so React can track identity across renders.

3. What React removes — and what it costs

▶ YouTube reference — the video for this lesson

React removes manual DOM updates, render-order bugs and a whole class of state/UI mismatches. It costs a build step, a bundle to download, and new failure modes (effect loops, stale closures). Skillzify chose vanilla deliberately: no build step, instant loads, and pages that embed Pyodide without toolchain friction. A content-heavy product dashboard at a company would usually choose React. Knowing both — and being able to defend either choice — is the interview-grade answer.

4. Next.js, at concept level

▶ YouTube reference — the video for this lesson

Next.js is React plus conventions: files in a folder become routes, and components can render on the server (fast first paint, good SEO) or the client (interactive). Learn the file-routing and server/client component ideas now; go deep only when a project needs it.

How this fits your stackReact is not in Skillzify — it's the industry layer on top. Your Phase 1 build (same app, both ways) is what turns this lesson from trivia into judgement.
Watch out — common mistakes
  • Putting everything in one giant component with prop drilling ten levels deep.
  • useEffect with missing dependencies causing stale data, or no dependency array causing effect loops.

function XpCounter() {
  const [xp, setXp] = useState(0);
  useEffect(() => { document.title = "XP: " + xp; }, [xp]);
  return <button onClick={() => setXp(xp + 10)}>+10 XP ({xp})</button>;
}

5 · Check

Say your answer out loud first, then reveal. Mark “I knew it” for +5 XP each.

What does calling setXp actually do in React?

It schedules a re-render with the new state value; React updates the DOM to match. You never manipulate DOM nodes yourself.

Give one honest reason Skillzify uses vanilla JS instead of React.

No build step and instant page loads, with simple embedding of heavy libraries like Pyodide; the site's interactivity doesn't need a framework's machinery.

6 · Interview

Explain useState and useEffect to a vanilla JS developer.

useState gives a component memory that triggers re-render on change; useEffect runs side effects after render, scoped by a dependency array.

When would you NOT choose React?

Content-first pages, tiny interactivity, or where a build step and bundle cost outweigh benefits — e.g. Skillzify's fast, framework-free pages.
