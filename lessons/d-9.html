Heaps & Priority Queues

The top-k pattern — keep only what matters

1. A heap is a partial order, not a sorted list

▶ YouTube reference — the video for this lesson

A heap is a binary tree where every parent is smaller than its children (min-heap) or larger (max-heap), stored compactly in an array. Only the top element is guaranteed — the rest is unordered. That partial order is the point: inserting and removing the top both cost O(log n), while building a heap from n elements costs O(n). If a problem only ever needs the smallest or largest element, a heap gives it without paying for a full sort.

2. The top-k pattern

▶ YouTube reference — the video for this lesson

Top-k problems are the heap's home ground. To find the k largest elements, keep a min-heap of size k: push each element, and whenever the heap exceeds k, pop the smallest. At the end the heap holds exactly the k largest, in O(n log k) time and O(k) space. The same shape solves Top K Frequent Elements — count frequencies first, then heap by count — and K Closest Points, where the heap is ordered by distance. The cue is the word top or closest combined with a large n.

3. Merging and scheduling with heaps

▶ YouTube reference — the video for this lesson

When several sorted streams must merge, a heap holding one current element from each stream always yields the next smallest in O(log k) per element — the engine of Merge K Sorted Lists. Scheduling problems use the same idea: always process the available job with the earliest deadline or shortest duration, which a heap supplies on demand. Whenever the next step is always the extreme of a changing set, a heap is the structure doing the choosing.

4. Heap versus sort: choosing the tool

▶ YouTube reference — the video for this lesson

Sorting costs O(n log n) once and then answers every order question in O(1); a heap costs O(n log k) for top-k and O(log n) per update, but shines when data arrives over time or k is much smaller than n. For a stream where the kth largest is asked repeatedly, a min-heap of size k answers in O(1) after each insertion. The interview move is to name both options and their costs, then pick by whether the data is static or streaming and whether k is small.

import heapq

def kth_largest(nums, k):
    heap = []
    for x in nums:
        heapq.heappush(heap, x)
        if len(heap) > k:
            heapq.heappop(heap)
    return heap[0]

# Min-heap of size k keeps only the k largest: O(n log k) time.

Why is building a heap O(n) instead of O(n log n)?

Most nodes sit near the leaves with tiny sift-down distances; summing the work over all levels gives O(n), not n times log n.

Why does the top-k pattern use a min-heap to find the k largest?

A min-heap of size k keeps the smallest of the k largest on top, so each new element is compared against exactly the threshold it must beat.

7 · Interview ▾

How do you find the median of a streaming sequence?

Keep a max-heap for the lower half and a min-heap for the upper half, balanced so their sizes differ by at most one. The median is a top element or the average of both.

When is a heap worse than just sorting?

When you need the fully sorted order, or when all elements are static and queried many times — a one-time O(n log n) sort then answers everything in O(1).
