Event Loop Deep — How JavaScript Never Blocks

Call stack, queues, and the single thread

1. One thread, three structures

▶ YouTube reference — the video for this lesson

JavaScript runs on a single thread with a call stack for what is executing now, a heap for objects, and queues for what is waiting. The event loop watches the stack: when it empties, it moves the next queued callback onto it. Nothing runs in parallel in your code; concurrency comes from the browser or Node doing slow work (network, timers, disk) off-thread and queueing the result.

2. Microtasks beat macrotasks

▶ YouTube reference — the video for this lesson

Promise callbacks go to the microtask queue; timers, events and I/O go to the task queue. After every stack emptying, the loop drains the entire microtask queue before touching one task. That is why a resolved promise's then always runs before a setTimeout with zero delay, and why a microtask that keeps queueing microtasks can starve everything else.

3. Blocking is a choice

▶ YouTube reference — the video for this lesson

A synchronous loop that runs for two seconds freezes the page for two seconds: no clicks, no paints, no timers fire, because the stack never empties. The fix is to chunk heavy work with setTimeout or queueMicrotask, move it to a Web Worker, or make it async so the loop can breathe between pieces. Skillzify's rendering stays fast because it never does heavy synchronous work on the main thread.

4. Async/await is syntax, not magic

▶ YouTube reference — the video for this lesson

await pauses the function, not the thread: the function returns a pending promise, the loop keeps serving other work, and the function resumes from the microtask queue when the awaited promise settles. The event loop is the machinery underneath every async function you have written.

Why does a resolved promise's then run before a zero-delay setTimeout?

Promise callbacks use the microtask queue, which the event loop drains fully before taking the next task from the timer queue.

Why does a long synchronous loop freeze the whole page?

The single thread is busy, so the call stack never empties and the event loop cannot run renders, timers or event handlers.

7 · Interview ▾

Explain the event loop in one minute.

Single thread plus queues: the loop moves callbacks from the task and microtask queues onto the call stack when it empties; slow work happens off-thread and its completion is queued.

What is the difference between the microtask queue and the task queue?

Microtasks (promises) drain fully before each task; tasks (timers, events, I/O) run one per loop turn.
