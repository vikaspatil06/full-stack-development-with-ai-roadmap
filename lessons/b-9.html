Version control from your first commit

Goal — by the end of this lessonBy the end you can initialise a repo, stage and commit changes, push to GitHub, and explain what each step actually does.

1. Git tracks snapshots, not files

▶ YouTube reference — the video for this lesson

Git records snapshots of your project over time. Each commit is a checkpoint with a message, a timestamp and a parent commit, forming a history you can rewind. Skillzify's entire history lives this way: every feature, fix and refactor is a commit you can inspect, which is why a bug can be traced to the exact change that introduced it.

2. The core workflow

▶ YouTube reference — the video for this lesson

Four commands cover daily work. git init creates a repo. git add stages changes into the next snapshot. git commit -m records the snapshot with a message. git push sends commits to GitHub, the remote copy. git status and git log show where you stand and what happened before.

▸ Code example — see the Code section below.

3. Commit messages are documentation

▶ YouTube reference — the video for this lesson

Write messages in the imperative mood describing what the change does: Add, Fix, Update, Remove. A future you, or a teammate, reads the log to understand why a line exists. Vague messages like update stuff are a small debt that compounds into an unreadable history.

4. Never commit secrets

▶ YouTube reference — the video for this lesson

API keys, passwords and service-account files must never reach GitHub. A .gitignore file lists paths Git skips, and a committed .env.example shows the shape of the config without the values. Skillzify's Firebase web config is public by design, but its Gemini key lives only in environment variables on Render.

5 · Check

Say your answer out loud first, then reveal. Mark “I knew it” for +5 XP each.

What is the difference between git add and git commit?

add stages changes into the next snapshot; commit records that staged snapshot into history. Nothing is saved until you commit.

Why does a .env file belong in .gitignore?

It holds secrets like API keys. Once pushed to GitHub, a secret is public forever — even deleting it later leaves it in history.

6 · Interview

Explain the difference between git and GitHub.

Git is the version-control tool that runs locally and tracks history; GitHub is a hosting service for Git repos that adds collaboration, pull requests and CI.

What does git status tell you?

Which files are staged, modified, untracked or clean, and which branch you are on — the state of your working tree versus the last commit.
