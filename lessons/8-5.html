Docker Intro

Images, containers, volumes — the same app, everywhere

1. Image versus container: the recipe and the meal

▶ YouTube reference — the video for this lesson

An image is a frozen filesystem plus instructions — the recipe. A container is a running instance of an image — the meal. You can run many containers from one image, stop and delete them, and the image is unchanged. That separation is the whole point: the image captures everything the app needs — Node version, dependencies, environment — so the app runs identically on your laptop, in CI, and on a server. Works on my machine stops being a defence when the machine is the same everywhere.

2. The Dockerfile: layer by layer

▶ YouTube reference — the video for this lesson

A Dockerfile builds an image in layers, one instruction at a time, and Docker caches each layer. Order matters for speed: copy the package manifest and install dependencies first, so a code change does not reinstall everything — only the final layer, copying your code, rebuilds. The result for Skillzify's backend is a small image that starts with one command and listens on a port you choose at runtime, with secrets passed as environment variables, never baked into the image.

3. Volumes and Compose: data that outlives the container

▶ YouTube reference — the video for this lesson

Containers are disposable by design — delete one and its filesystem goes with it. A volume is storage that lives outside the container, so a database keeps its data across restarts and redeploys. Docker Compose ties it together: one YAML file describing the app, the database and their volumes and networks, started with a single command. For local development it replaces a page of setup instructions with docker compose up.

▸ Code example — see the Code section below.

Never put a secret in a Dockerfile or an image layer — layers are history, and a deleted secret in a later layer is still retrievable from the earlier one.

# Dockerfile for the Skillzify Node backend
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY server.js ./
ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "server.js"]
# Build: docker build -t skillzify-api .
# Run:   docker run -p 3000:3000 -e GEMINI_API_KEY=... skillzify-api

What is the difference between an image and a container?

An image is the frozen template; a container is a running instance of it. Many containers can run from one image, and deleting a container leaves the image unchanged.

Why copy package.json and install before copying code in a Dockerfile?

Layer caching: dependencies install once and are reused until the manifest changes, so code edits only rebuild the final layer.

7 · Interview ▾

When is Docker the wrong tool?

For tiny static sites with no backend, or when the platform already handles the runtime — Render or a serverless function may be simpler than managing containers yourself.

A container restart wipes your database. What went wrong?

The data lived in the container's filesystem instead of a volume. Volumes persist outside the container's lifecycle.
