1. Authentication vs authorisation

▶ YouTube reference — the video for this lesson

Authentication proves who you are; authorisation decides what you may do. A login checks credentials and issues proof; a protected route checks that proof and the rules. Confusing the two is how apps end up letting any logged-in user read anyone else's data — the exact bug Skillzify's Firestore rules exist to prevent.

2. How a JWT works

▶ YouTube reference — the video for this lesson

A JSON Web Token has three parts: a header naming the algorithm, a payload with claims like the user id and expiry, and a signature made by hashing the first two parts with a server secret. The server verifies the signature on every request — no database lookup, no session store. Anyone can read the payload, so it must never contain secrets; only the server can forge a valid signature.

3. Passwords and tokens, done right

▶ YouTube reference — the video for this lesson

Passwords are never stored in plain text — they are hashed with a slow algorithm like bcrypt, so a leaked database does not leak logins. Tokens expire (minutes to hours) and are refreshed, limiting the damage if one is stolen. And the signing secret lives in an environment variable, never in code or git.

4. Why Skillzify uses Firebase Auth

▶ YouTube reference — the video for this lesson

Building auth correctly is a security speciality: hashing, tokens, refresh, reset flows, brute-force protection. Firebase Auth provides all of it, including Google sign-in, and the server verifies Firebase ID tokens instead of issuing its own. Hand-rolled auth is a learning exercise; production auth is a solved problem you buy, not one you reinvent.

3 · Code

const jwt = require("jsonwebtoken");
const SECRET = process.env.JWT_SECRET;

function auth(req, res, next) {
  const token = (req.headers.authorization || "").replace("Bearer ", "");
  try {
    req.user = jwt.verify(token, SECRET);   // throws if invalid/expired
    next();
  } catch (err) {
    res.status(401).json({ error: "Invalid or expired token" });
  }
}
app.get("/api/me", auth, (req, res) => res.json({ uid: req.user.uid }));

Why must a JWT payload never contain a password or secret?

The payload is only base64-encoded, not encrypted — anyone holding the token can read it. Only the signature is secret-protected.

What does jwt.verify do that simply decoding the token does not?

It checks the signature against the server secret and the expiry, proving the token was issued by the server and is still valid.

6 · Interview

Explain JWT authentication end to end.

Login verifies credentials and issues a signed token; the client sends it as a Bearer header; the server verifies signature and expiry per request, with no session store.

Why is Firebase Auth a better choice than hand-rolled JWT auth for Skillzify?

It provides hashing, token refresh, reset flows, brute-force protection and social login, maintained by specialists — hand-rolled auth invites subtle security bugs.
