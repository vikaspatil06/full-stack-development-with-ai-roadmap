TypeScript Intro — Types for JavaScript Developers

Catch the bug before it runs

Goal — by the end of this lessonBy the end you can add types to JavaScript code, choose between interfaces and type aliases, write a simple generic function, configure tsconfig, and migrate one JavaScript file to TypeScript.

1. Why TypeScript: errors at write time, not run time

▶ YouTube reference — the video for this lesson

JavaScript only discovers type errors when the code runs — a misspelled property returns undefined silently, and passing a string where a number belongs produces NaN far from the cause. TypeScript adds a static type layer that is checked before the code ever runs, then compiles away to plain JavaScript. The editor underlines the mistake as you type, and renaming a field updates every use automatically.

Skillzify v2 is untyped vanilla JavaScript, so a renamed lesson field or a wrong argument shape is only found by clicking through pages. TypeScript would catch exactly that class of bug: a lesson object missing its xp field, or a function called with a string instead of a number, fails the build instead of failing silently in a learner's browser.

2. The basic types and annotations

▶ YouTube reference — the video for this lesson

You annotate variables, parameters and return values: string, number, boolean, arrays like string[], and unions like string | number for values that can be either. TypeScript also infers types from initial values, so most variables need no annotation at all — annotate function boundaries and let inference handle the rest. The any type opts out of checking entirely and should be treated as a warning sign, not a convenience.

3. Interfaces, type aliases and generics

▶ YouTube reference — the video for this lesson

Both interface and type describe object shapes. Interfaces can be extended and merged, which suits public object contracts; type aliases can also name unions, tuples and primitives, which makes them more flexible. In practice: use interface for object shapes you expect to extend, type for everything else, and be consistent. Generics let a function or type work over many types while staying checked — a first<T> function returns whatever element type the array holds, instead of collapsing everything to any.

4. tsconfig and migrating a file

▶ YouTube reference — the video for this lesson

The tsconfig.json file controls strictness and output. The setting that matters most is strict: true, which turns on null checks and other safety rules; migrating a file means renaming it to .ts, fixing the errors the checker reports from the outside in, and adding types at the boundaries first. Migrate leaf files before central ones, keep allowJs on so untyped files still compile, and never migrate by sprinkling any — that keeps the cost of TypeScript and throws away the benefit.

interface Lesson {
  id: string;
  title: string;
  xp: number;
}

function totalXp(lessons: Lesson[]): number {
  return lessons.reduce((sum, l) => sum + l.xp, 0);
}

function first<T>(items: T[]): T | undefined {
  return items[0];
}

const lessons: Lesson[] = [{ id: "b-1", title: "Intro", xp: 20 }];
console.log(totalXp(lessons), first(lessons)?.title);

What does TypeScript compile to, and when are types checked?

It compiles to plain JavaScript with all types erased. Types are checked at build time by the compiler, never at run time — there is no type information left in the output.

Why is any dangerous?

any disables type checking for that value, so errors pass silently and spread to everything the value touches. It removes the benefit of TypeScript while keeping its cost.

When do you choose an interface over a type alias?

For object shapes you expect to extend or merge, like component props or API models. Type aliases are better for unions, tuples and naming primitive combinations.

What does a generic type parameter buy you over any?

It preserves the relationship between input and output types: first of a string array returns a string, checked by the compiler, instead of an unchecked any.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “Type annotation”?

A declared type on a variable, parameter or return value, checked by the compiler and erased from the output JavaScript.

What is “Type inference”?

TypeScript deducing a type from the initial value, so most variables need no explicit annotation.

What is “Union type”?

A type that allows one of several types, written with a pipe, like string | number.

What is “Interface”?

A named object shape that can be extended and declaration-merged; the standard way to type objects and props.

What is “Generic”?

A type parameter that lets code work over many types while keeping them checked, like a first&lt;T&gt; function.

What is “strict mode”?

The tsconfig flag that enables the full set of safety checks, including strict null checking.

7 · Interview ▾

Your team says TypeScript slows them down. What is your honest answer?

It adds upfront annotation cost, repaid by catching contract errors at build time, safer refactors, and editor autocomplete across the codebase. The trade favours any project that will live longer than a prototype.

How do you migrate a large JavaScript codebase to TypeScript?

Incrementally: enable allowJs, rename leaf files first, type the boundaries, keep strict mode on for new files, and fix errors file by file rather than in one big-bang rewrite.
