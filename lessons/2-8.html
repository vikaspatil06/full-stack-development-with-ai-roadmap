Error Handling — Exceptions, EAFP, and Clean Failures

Code that fails gracefully instead of crashing

1. Exceptions are the error system

▶ YouTube reference — the video for this lesson

When Python cannot do something — a missing file, a bad conversion, a missing key — it raises an exception that unwinds the call stack until something catches it. Uncaught, it crashes the program with a traceback. The traceback is a gift: it names the error type, the message, and the exact line and call chain that failed.

2. try/except/else/finally

▶ YouTube reference — the video for this lesson

try holds the risky code, except catches specific errors, else runs only when nothing failed, and finally always runs for cleanup. Catch the narrowest exception you can name — a bare except hides real bugs, including typos and keyboard interrupts, and makes debugging miserable.

▸ Code example — see the Code section below.

3. EAFP: easier to ask forgiveness

▶ YouTube reference — the video for this lesson

Python's idiom is to try the operation and catch the failure, rather than checking every precondition first. Try to open the file and catch FileNotFoundError, instead of checking existence and then opening — the check-then-act version has a race: the file can vanish between the two steps.

4. Raising useful errors

▶ YouTube reference — the video for this lesson

When your own code detects bad input, raise a specific exception with a message that says what was wrong and what was expected. Skillzify's flowchart parser raises ValueError with the offending line number, so a learner's broken code produces a helpful message instead of a crash. A good error message names the value that failed and the value that was expected, so the person reading it can fix the input without opening the source code.

3 · Code

def load_scores(path):
    try:
        with open(path, encoding="utf-8") as f:
            data = json.load(f)
    except FileNotFoundError:
        return {"scores": []}
    except json.JSONDecodeError as err:
        raise ValueError("Bad JSON in " + path + ": " + str(err))
    else:
        return data

Why catch FileNotFoundError instead of a bare except?

A bare except catches everything, including typos and interrupts, hiding real bugs. Catching the specific error keeps other failures visible.

What is EAFP and why does Python prefer it?

Easier to ask forgiveness than permission: try the operation and handle the failure. It avoids check-then-act races and reads more directly.

6 · Interview

What is the difference between except Exception and a bare except?

except Exception catches most errors but lets system-level ones like KeyboardInterrupt through; a bare except catches literally everything, including those.

What is the difference between else and finally in a try block?

else runs only when no exception occurred; finally runs always, for cleanup, whether or not an exception was raised.
