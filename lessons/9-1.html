React Hooks Deep — useEffect, useContext & Custom Hooks

State, effects and reuse without classes

1. Why hooks exist: the class lifecycle problem

▶ YouTube reference — the video for this lesson

Before hooks, React components that needed state or side effects had to be classes, and related logic was split across lifecycle methods: fetching data in componentDidMount, updating it in componentDidUpdate, and cleaning up in componentWillUnmount. One feature ended up scattered across three places. Hooks let a plain function component own state with useState and run side effects with useEffect, so all the code for one concern sits together in one place.

Skillzify v2 solves the same problem without a framework: its vanilla JavaScript manually re-renders lists and progress after every change. Hooks are the framework answer to that exact pain — instead of you remembering to update the DOM, you describe what the UI should look like for a given state and React updates it for you.

2. useEffect: dependencies and cleanup

▶ YouTube reference — the video for this lesson

useEffect runs after render. The dependency array decides when it re-runs: an empty array means once on mount, an array with values means whenever those values change, and no array means after every render. The function you optionally return is the cleanup: React calls it before re-running the effect and when the component unmounts. Timers, subscriptions and event listeners must always be cleaned up, or they leak and fire twice.

The most common beginner bug is a missing dependency: the effect reads a variable but never re-runs when it changes, so the UI shows stale data. Treat the dependency array as a promise — every reactive value the effect reads belongs in it.

3. useContext and useRef

▶ YouTube reference — the video for this lesson

useContext reads shared data — the signed-in user, the theme, the XP total — from a provider high in the tree, without passing props through every component in between. It is the right tool for truly global, slowly-changing values, and the wrong tool for fast-changing state, because every consumer re-renders when the context value changes. useRef holds a mutable value that survives re-renders without causing one: a DOM node to focus, a timer id, or a previous value. Changing a ref never re-renders, which is exactly what you want for values the screen does not display.

4. Custom hooks: reuse the logic, not the markup

▶ YouTube reference — the video for this lesson

A custom hook is just a function whose name starts with use and which calls other hooks. useFetch packages the fetch-loading-error dance; useLocalStorage packages reading and writing persisted state. The rule that makes it all work: hooks are always called unconditionally at the top level, in the same order every render, because React tracks them by call order. In Skillzify, the equivalent shared helpers live in one JavaScript file every page loads — custom hooks are the same idea, but tied to component state.

4 · Code ▾

▶ Run works for JavaScript snippets below — it runs in a sandboxed worker with a 2-second timeout. Python, HTML and CSS snippets are read-only here.

import { useState, useEffect } from "react";

function useFetch(url) {
  const [data, setData] = useState(null);
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);
  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    fetch(url)
      .then((r) => r.json())
      .then((json) => { if (!cancelled) { setData(json); setLoading(false); } })
      .catch((e) => { if (!cancelled) { setError(e); setLoading(false); } });
    return () => { cancelled = true; };
  }, [url]);
  return { data, error, loading };
}

What does the cleanup function returned from useEffect do?

React calls it before re-running the effect and when the component unmounts. It is where you cancel subscriptions, clear timers and ignore in-flight fetches so nothing leaks.

Why must hooks be called unconditionally at the top level?

React tracks hooks by call order between renders. A conditional hook would shift that order, so state would be matched to the wrong hook.

When is useContext the wrong choice for state?

When the value changes frequently, because every consumer re-renders on each change. Fast-changing state belongs in local state or a store with selective subscriptions.

What is the difference between useState and useRef?

useState triggers a re-render when it changes and is for values the UI displays. useRef persists a mutable value across renders without re-rendering, for DOM nodes, timers and previous values.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “useEffect”?

A hook that runs side effects after render, re-running when its dependency array values change, with an optional cleanup function.

What is “Dependency array”?

The list of reactive values an effect depends on; React re-runs the effect when any of them changes.

What is “Cleanup function”?

The function returned from useEffect, called before re-running the effect and on unmount — where timers and subscriptions are torn down.

What is “useContext”?

A hook that reads a value from the nearest context provider, avoiding prop drilling for global, slowly-changing data.

What is “useRef”?

A hook holding a mutable value that persists across renders without causing one — used for DOM nodes, timers and previous values.

What is “Custom hook”?

A function starting with use that calls other hooks to package reusable stateful logic, like useFetch or useLocalStorage.

7 · Interview ▾

Explain the useEffect dependency array to a beginner.

It lists the values the effect depends on. React re-runs the effect only when one of them changes; an empty array means run once on mount. Every reactive value the effect reads should be listed, or the effect will use stale data.

How would you stop a fetch from updating state after the component unmounts?

Use a cancelled flag or an AbortController in the effect cleanup. The cleanup runs on unmount, sets the flag or aborts the request, and the response handler checks it before calling setState.
