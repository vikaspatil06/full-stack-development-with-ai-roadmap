1. Composables: functions that describe UI

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

If this looks like a React component, that's because it is the same idea: a function of data returns a UI description. You never inflate layouts or hunt views by id.

2. State and recomposition

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

When state changes, Compose recomposes — re-runs the affected composables with new values and updates only what differs. remember keeps state across recompositions. The discipline mirrors React exactly: UI is a function of state; mutate state, never the UI directly.

3. Material 3 theming

▶ YouTube reference — the video for this lesson

Skillzify's app uses Material 3: colour schemes, typography scales and component styles flow from a theme, the same "change variables in one place" idea as CSS variables in Lesson 0.3 — third platform, same principle.

Why this module is shorter than it looksYou already paid the conceptual cost in Module 1 (components, state, derived UI). Android's remaining difficulty is platform knowledge — lifecycle, navigation, the build system — which the next two lessons cover.

3 · Code

@Composable
fun LessonCard(lesson: Lesson) {
    Card(modifier = Modifier.padding(8.dp)) {
        Column(modifier = Modifier.padding(16.dp)) {
            Text(lesson.title, style = MaterialTheme.typography.titleMedium)
            Text(lesson.xp.toString() + " XP")
        }
    }
}
var xp by remember { mutableStateOf(0) }
Button(onClick = { xp += 10 }) { Text("Earn XP (" + xp + ")") }

5 · Check

Say your answer out loud first, then reveal. Mark “I knew it” for +5 XP each.

What triggers recomposition, and what does it do?

A state change; Compose re-runs the composables that read that state with the new value and updates only the differing UI.

Name the exact React concept that matches a @Composable function.

A function component: data/props in, UI description out, re-rendered when its state inputs change.

6 · Interview

Explain declarative UI to someone who only knows the old View system.

You describe what the UI should look like for a given state; the framework diffs and updates. No manual view lookups or imperative updates — same shift as React on web.

Where should screen state live as an app grows?

In a ViewModel (next lesson) that survives configuration changes, exposing state the composables render — composables stay dumb and testable.
