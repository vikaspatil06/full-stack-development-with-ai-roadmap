1. Embeddings: meaning as numbers

▶ YouTube reference — the video for this lesson

An embedding model converts text into a vector — say 768 numbers — positioned so that texts with similar meaning sit close together (Lesson 2.4's arrays, with semantics). "How do loops work?" and "Explain iteration in Python" land near each other without sharing many words. Similarity is then arithmetic: cosine similarity or dot product between vectors.

2. The RAG pipeline

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

Key craft points: chunking (small enough to be specific, big enough to keep context — a reference entry per chunk suits Skillzify), top-k (3–5 chunks is a sane start; more chunks = more tokens and more noise), and grounding rules in the prompt — "answer only from the provided entries; say you don't know otherwise" — plus showing the source — that combination is what turns a hallucinating model into a citing assistant.

3. RAG vs fine-tuning vs long prompt — the decision

▶ YouTube reference — the video for this lesson

  • Long prompt: your whole knowledge fits the window and changes rarely → simplest. Skillzify today: correct choice — plain API calls, no retrieval needed yet.
  • RAG: knowledge is large, changes often, or must be cited → retrieval wins.
  • Fine-tuning: you need a consistent style/behaviour, not more facts. Expensive, slow to update, and a poor way to teach facts.
Vector stores, honestlyChroma runs locally for learning; Pinecone is managed cloud. At Skillzify-reference scale (127 entries), even a JSON file + NumPy dot products in memory is a legitimate v1 — reach for infrastructure when scale demands it, not before.

Why chunk documents before embedding them?

Retrieval must return specific, relevant passages; embedding whole documents averages their meaning away and wastes context window on irrelevant text.

A client wants the model to 'learn our 500-page manual'. RAG or fine-tune?

RAG — the need is factual, changing, citable knowledge. Fine-tuning teaches behaviour/style, not updatable facts.

7 · Interview ▾

Explain RAG end to end, briefly.

Offline: chunk documents, embed chunks, store vectors. Online: embed the question, retrieve nearest chunks, place them in the prompt with grounding instructions, generate an answer that cites the retrieved sources.

How do you evaluate whether your RAG is working?

A fixed question set with known source entries: measure retrieval hit-rate (did the right chunk appear in top-k?) and answer faithfulness (claims supported by the chunk?), per change.
