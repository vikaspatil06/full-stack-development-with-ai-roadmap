this & Prototypes — How JavaScript Objects Really Work

The prototype chain, demystified

1. this depends on the call, not the definition

▶ YouTube reference — the video for this lesson

In JavaScript, this is set by how a function is called. Called as a method, this is the object before the dot. Called plainly, this is undefined in strict mode. Called with new, this is the fresh object being built. Arrow functions are the exception: they inherit this from the surrounding scope and cannot be rebound. Most this bugs come from passing a method as a callback and losing its object.

2. Prototypes: shared behaviour

▶ YouTube reference — the video for this lesson

Every object has a hidden link to a prototype object. When you read a property the object lacks, JavaScript walks up the prototype chain until it finds it. Methods live on the prototype, not on each instance, so a thousand lesson objects share one set of methods instead of each carrying copies.

▸ Code example — see the Code section below.

3. Classes are sugar

▶ YouTube reference — the video for this lesson

The class keyword writes the same prototype machinery with cleaner syntax: methods go on the prototype automatically, and extends sets up the chain. Skillzify's vanilla code mostly uses factory functions and plain objects instead, but interviewers and libraries assume you can read class syntax fluently.

4. When this goes wrong

▶ YouTube reference — the video for this lesson

Event handlers, timers and array callbacks all change the call site, so this changes too. The fixes are an arrow function that captures the outer this, bind to lock it, or avoiding this entirely by using closures and plain data — the approach Skillzify's modules mostly take.

3 · Code

function Lesson(id, title) {
  this.id = id;
  this.title = title;
}
Lesson.prototype.summary = function () {
  return this.id + ": " + this.title;
};
const l = new Lesson("b-1", "Intro");
console.log(l.summary());   // "b-1: Intro"
console.log(l.hasOwnProperty("summary")); // false — it lives on the prototype

What decides the value of this inside a function?

How the function is called: as a method it is the object before the dot; plainly it is undefined in strict mode; with new it is the new object; arrows inherit it.

Where do methods live when you use a constructor function?

On the constructor's prototype object, shared by all instances. hasOwnProperty on an instance returns false for them.

6 · Interview

Explain the prototype chain in one minute.

Objects link to a prototype; a missing property is looked up the chain until found or the chain ends at null. Methods live on prototypes so instances share them.

Why does passing obj.method as a callback break this?

The call site changes, so this is no longer obj. Fix it with an arrow wrapper, bind, or by not relying on this.
