Error Handling & Debugging — Finding Bugs Like a Professional

Try/catch, stack traces, and DevTools as a lab

1. Errors are values with a story

▶ YouTube reference — the video for this lesson

JavaScript errors are objects with a name, a message and a stack trace showing the call chain that led to the failure. ReferenceError means a name does not exist, TypeError means a value was used the wrong way (like calling a non-function), and SyntaxError means the code could not even parse. Reading the error type first, before the message, already narrows the search.

2. try/catch/finally

▶ YouTube reference — the video for this lesson

Wrap code that can fail — JSON parsing, network calls, localStorage access — in try, handle the failure in catch, and put cleanup in finally, which runs either way. Skillzify wraps every localStorage read in try/catch because one corrupted value must never take down a page. Catch only what you can handle; rethrow the rest.

▸ Code example — see the Code section below.

3. Debugging with breakpoints

▶ YouTube reference — the video for this lesson

console.log is the start, not the end. In DevTools Sources, click a line number to set a breakpoint, reload, and the code pauses there: inspect every variable, step line by line, and watch expressions change. Conditional breakpoints pause only when a value matches, which is how you catch a bug that happens once in a thousand iterations.

4. A debugging method

▶ YouTube reference — the video for this lesson

Reproduce it reliably, read the exact error, form one hypothesis, test it with the smallest change, and verify the fix removes the symptom without breaking anything else. Guess-and-check feels faster and is slower; a written hypothesis is what separates a professional debug session from an afternoon lost to random edits.

3 · Code

function loadProgress() {
  try {
    const raw = localStorage.getItem("skillzify_progress");
    return raw ? JSON.parse(raw) : {};
  } catch (err) {
    console.warn("Corrupt progress, starting fresh:", err.message);
    return {};
  } finally {
    console.log("Progress load attempted");
  }
}

Why wrap localStorage reads in try/catch?

Stored data can be corrupted, the quota can be exceeded, or storage can be disabled — any of which throws, and one throw must not crash the page.

When should you rethrow an error instead of handling it?

When the local code cannot meaningfully recover — log context, then let the caller or a top-level handler decide.

6 · Interview

What is the difference between a SyntaxError and a TypeError?

SyntaxError means the code could not parse at all; TypeError means parsed code ran but used a value incorrectly, like calling something that is not a function.

Walk me through debugging a bug you cannot reproduce reliably.

Narrow the conditions, add logging at boundaries, use conditional breakpoints, and bisect recent changes until the trigger is isolated.
