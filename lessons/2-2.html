1. Lists: ordered and mutable

▶ YouTube reference — the video for this lesson

Lists hold an ordered sequence you can index, slice, append to and sort. Indexing and appending are fast, but inserting in the middle or checking membership with in scans the whole list. Use lists when order matters and you mostly append and iterate — like Skillzify's ordered lesson arrays.

2. Dicts: lookup by key

▶ YouTube reference — the video for this lesson

Dicts map keys to values with average O(1) lookup, insert and delete. They are Python's default structure for records, configs and indexes. Skillzify's flowchart parser builds nested dicts as its intermediate JSON, and the web side consumes the same shape — one data format understood by both languages.

▸ Code example — see the Code section below.

3. Sets: uniqueness and membership

▶ YouTube reference — the video for this lesson

Sets hold unique items with O(1) membership tests. Need to know whether a lesson was already counted, or deduplicate a list? A set is the answer. Checking in on a list inside a loop is the classic O(n squared) accident; a set makes the same check constant-time.

4. Tuples: fixed records

▶ YouTube reference — the video for this lesson

Tuples are immutable, ordered records — a coordinate, a lesson id plus a score, a key for a dict. Immutability makes them hashable, so they can be dict keys and set members where lists cannot. Choosing tuple over list signals intent: this record is complete and will not change.

3 · Code

seen = set()
progress = {"p-1": True, "p-2": False}
scores = [88, 92, 74, 91]
record = ("p-1", 88)          # tuple: a fixed, immutable pair
for lesson_id in progress:
    if lesson_id not in seen:
        seen.add(lesson_id)
print(len(seen), max(scores))  # 2 92

Why is checking membership in a set faster than in a list?

A set is a hash table, so lookup is average O(1); a list must scan each element, O(n).

When would you choose a tuple over a list?

When the record is fixed and should never change — immutability documents intent and lets it be used as a dict key or set member.

6 · Interview

List vs tuple vs set vs dict — one line each.

List: ordered mutable sequence. Tuple: fixed immutable record. Set: unique items with fast membership. Dict: key-to-value lookup.

What is the complexity trap of using in on a list inside a loop?

Each check scans the list, so the loop becomes O(n squared). A set makes each check O(1).
