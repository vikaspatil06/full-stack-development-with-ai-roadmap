1. Structure vs presentation

▶ YouTube reference — the video for this lesson

HTML's only job is meaning and structure: this is a heading, this is navigation, this is the main content. Colour, spacing and layout belong to CSS; behaviour belongs to JavaScript. When HTML tries to do CSS's job (old-school font tags, inline styles everywhere), pages become impossible to restyle.

4. Empty divs that JavaScript fills

▶ YouTube reference — the video for this lesson

Every Skillzify page contains <div id="site-nav"></div> and an empty footer div. The nav HTML is written once, in nav.js, which injects it into that placeholder on all 17 pages. Change the nav in one file and every page updates — the same "don't repeat yourself" instinct as a function.

Accessibility is not optional polishSemantic tags, one h1 per page, alt text on images and real buttons (not clickable divs) are what make a page usable with a screen reader or a keyboard. Interviewers ask about this.
Watch out — common mistakes
  • Building pages from divs alone when semantic tags exist — hurts accessibility and SEO.
  • Skipping the viewport meta tag, then debugging 'broken' mobile layouts for hours.

What breaks on phones if the viewport meta tag is missing?

Mobile browsers assume a ~980px layout width and scale the page down, so text is tiny and responsive media queries keyed to device width never apply correctly.

Why is #site-nav empty in the HTML?

nav.js injects the shared navigation into it at runtime, so the nav is written once and reused across all 17 pages.

7 · Interview ▾

What does semantic HTML buy you?

Meaning for browsers, screen readers and search engines: structure that assistive tech can navigate and crawlers can understand, plus more maintainable markup.

Why is the viewport meta tag essential for mobile?

Without it mobile browsers assume ~980px width and scale down; with it, layout width equals device width so responsive CSS applies correctly.
