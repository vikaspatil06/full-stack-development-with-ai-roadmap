Sorting & Searching (Binary Search)

Sorted input is a superpower — halve the search space

1. Sorting first is often the whole solution

▶ YouTube reference — the video for this lesson

Comparison sorting costs O(n log n), and paying it once can unlock linear patterns everywhere else: two pointers need sorted input, duplicates become adjacent, and binary search becomes possible. That is why so many interview solutions start with a sort — the O(n log n) is cheap compared with the O(n²) it replaces. Know your sorts: merge sort is stable and always O(n log n), quicksort is fast in practice but O(n²) worst case, and counting sort is O(n + k) when values are bounded.

2. The binary search invariant

▶ YouTube reference — the video for this lesson

Binary search works on any sorted input, and the correct way to write it is from its invariant: the answer, if it exists, is always inside [lo, hi]. Each step compares the middle element and discards the half that cannot contain the answer, halving the range until lo passes hi. The classic bugs — infinite loops and missed elements — all come from updating lo and hi inconsistently with the invariant. Write the invariant as a comment, use lo = mid + 1 and hi = mid − 1, and the loop terminates.

3. Binary search on the answer

▶ YouTube reference — the video for this lesson

The most powerful form of binary search does not search an array at all: it searches a range of possible answers. In Koko Eating Bananas, the answer is a speed between 1 and the maximum pile; a feasibility check — can Koko finish at this speed — is monotonic, so binary search finds the smallest feasible speed. The recognition cue is a question asking for the minimum or maximum value satisfying a yes-or-no condition that flips once as the value grows.

4. Rotated arrays and edge cases

▶ YouTube reference — the video for this lesson

A rotated sorted array is still searchable in O(log n) because one half is always sorted: compare the middle element with the ends to find which half is ordered, then check whether the target lies inside it. The same invariant thinking applies, but the branch logic doubles, so tracing a three-element example is essential. Always test the unrotated case, the single-element case, and the target at both ends — these are where rotated-array solutions silently fail.

def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1

# Invariant: the target, if present, is in [lo, hi]. O(log n) time.

What is the loop invariant of binary search, and why does it prevent infinite loops?

The target, if present, is always within [lo, hi]. Each step shrinks that range by at least half, so the loop must terminate.

When can you binary-search an answer that is not in any array?

When the question asks for a minimum or maximum value and the feasibility check is monotonic — feasible answers stay feasible as the value grows, so the boundary is searchable.

7 · Interview ▾

Why is merge sort stable and quicksort not, and when does it matter?

Merge sort preserves the order of equal elements; quicksort's swaps do not. Stability matters when sorting by one key after another, like sorting records by date then by name.

How do you find the minimum in a rotated sorted array in O(log n)?

Compare mid with the right end: if nums[mid] is greater, the minimum is in the right half; otherwise it is in the left half including mid. Repeat until one element remains.
