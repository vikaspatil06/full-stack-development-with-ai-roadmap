Beyond a textarea: highlighting, completion, lint and themes

1. CodeMirror 6 is a box of composable extensions

▶ YouTube reference — the video for this lesson

CodeMirror 6 is not one editor with settings — it is a small core plus extensions that each add one capability: line numbers, syntax highlighting, autocompletion, search, themes. You build an editor by listing the extensions you want, and two editors can share most of a list while differing in one piece. That composition model is why Skillzify can use the same editor for the Python runner and the flowchart code view with different language support: same core, different extension lists.

2. Language support is a data package

▶ YouTube reference — the video for this lesson

Syntax highlighting comes from a language package — @codemirror/lang-python for Python — which parses the code and tags each token so a theme can colour it. Autocompletion is a separate extension that suggests identifiers as you type, fed by a completion source you can extend with Skillzify's own lesson vocabulary. The key insight is that highlighting is parsing: the editor genuinely understands the code's structure, which is why it can also bracket-match, fold blocks and indent correctly.

3. Linting: your own diagnostics, live

▶ YouTube reference — the video for this lesson

The lint extension shows squiggles under problems, driven by a lint source — a function that receives the document and returns diagnostics with positions and severities. You can wire it to Pyodide: run a syntax check on each edit and surface Python's own error messages in the editor, at the exact line. That closes the loop between writing and running: the editor stops being a fancy textarea and becomes a small IDE.

▸ Code example — see the Code section below.

Extensions are values in an array — swap one, and the editor's behaviour changes without touching anything else. That is the whole design philosophy in one line.

3 · Code

import { EditorView, basicSetup } from "codemirror";
import { python } from "@codemirror/lang-python";
import { autocompletion } from "@codemirror/autocomplete";
import { linter } from "@codemirror/lint";

const view = new EditorView({
  doc: "print('hello')\n",
  extensions: [
    basicSetup,
    python(),
    autocompletion(),
    linter(async (view) => checkWithPyodide(view.state.doc.toString()))
  ],
  parent: document.getElementById("editor")
});

Why does CodeMirror 6 use extensions instead of configuration flags?

Extensions compose: each adds one capability, so editors share most of a list and differ in one piece, instead of inheriting a fixed feature set.

What does a lint source receive and return?

It receives the editor view and document, and returns diagnostics — each with a position, severity and message — which the editor renders as squiggles.

6 · Interview

How would you add Skillzify lesson keywords to autocompletion?

Write a custom completion source that merges the language's completions with your own list, and register it as an extension alongside the default one.

Highlighting looks cosmetic — why is it actually parsing?

Because the language package tokenises the code structurally, which is what also enables bracket matching, folding and correct indentation. Colour is the visible side effect.
