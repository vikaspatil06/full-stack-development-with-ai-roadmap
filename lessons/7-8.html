1. One project, two platforms

▶ YouTube reference — the video for this lesson

The Android app registers with the same Firebase project (skillzify-1d0f2) and pulls dependencies via the Firebase BoM (33.7.0 in Skillzify) — a bill of materials that pins mutually compatible versions of Auth, Firestore and friends, the Android answer to package.json discipline. Sign-in is the same Email/Password; the document is the same users/{uid}.

2. The merge rules are a protocol, not a preference

▶ YouTube reference — the video for this lesson

Lesson 4.3's five merge rules are implemented identically in Kotlin. This is the part of cross-platform development nobody warns you about: the shared contract lives in two languages, and the only defence is a written spec plus scenario tests run against both implementations (disjoint lessons, XP max, streak dates).

3. Chaquopy: Python inside Android

▶ YouTube reference — the video for this lesson

Skillzify's Android compiler can't use Pyodide — there's no browser. Chaquopy (15.0.1) embeds a real CPython 3.11 interpreter in the APK, so learner code runs natively and offline. Kotlin calls into Python modules and gets results back across the bridge. Same product promise ("Python runs on your device"), two completely different mechanisms — a perfect example of platform-appropriate implementation behind one feature.

4. The build system, without fear

▶ YouTube reference — the video for this lesson

Gradle 8.10.2 + Android Gradle Plugin 8.5.2 on JDK 17, compileSdk 34, minSdk 24. CI (Lesson 8.2) runs the same build on GitHub Actions. When a build fails, read the first error, not the cascade — and never mix Gradle DSL dialects in one file, a scar Skillzify's own CI history carries.

What is the Firebase BoM and what problem does it solve?

A bill of materials pinning compatible versions of all Firebase libraries, so adding Auth + Firestore can't produce a mismatched-version build failure.

How does Android run Python without a browser?

Chaquopy embeds the CPython interpreter inside the APK; Kotlin calls Python modules natively, fully offline.

7 · Interview ▾

Your app exists on web and Android with shared data. What's the hardest part?

Not the UI — the shared contract: one document schema and identical merge semantics implemented in two languages, verified by cross-platform scenario tests.

Why embed Python in the APK instead of calling a server to run code?

Offline use, zero per-run server cost and latency — at the price of APK size and an embedded-runtime maintenance duty.
