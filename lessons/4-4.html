Sync & Merge Rules

How web and Android share one truth without losing XP

1. The problem: two devices, one document, offline gaps

▶ YouTube reference — the video for this lesson

A learner earns 50 XP on Android on a train (offline), then does a lesson on web before the phone syncs. Both devices hold a version of users/{uid}. Naive "last write wins" for the whole document destroys one side's progress — guaranteed data loss in normal use.

2. The fix: merge per field, by meaning

▶ YouTube reference — the video for this lesson

Skillzify's sync.js merges field by field, with a rule chosen from what the field means:

▸ Code example — see the Code section below.

The rules are byte-identical in the web and Android codebases — a rule that differs by platform is a bug that only appears after real learners lose data. Notice that "last write wins" is right for exactly one field: profile, where the newest edit expresses current intent and nothing accumulates.

3. The general method

▶ YouTube reference — the video for this lesson

For any new field ask: does it accumulate (union/max), does it describe now (last-write-wins), or is it a collection of independent facts (per-item merge)? Bookmarks accumulate → union with tombstones for removals. Settings describe now → last-write-wins. Quiz attempts are independent facts → per-attempt merge by id.

Edge case from productionThe Skill Passport privacy flag is stored per-uid so it survives sign-out and doesn't leak between users sharing a browser — and it fails closed (private) if anything goes wrong. When in doubt, the safe default wins.

3 · Code

lessonsDone : UNION            // completed on either device = completed
xp          : MAX              // XP never goes backwards
streak      : LATER DATE WINS  // the fresher streak record is truer
exercises   : PER-FIELD MERGE  // each exercise resolved independently
profile     : LAST WRITE WINS  // name/avatar edits — newest is the intent

5 · Check

Why not use last-write-wins for the whole progress document?

Because devices diverge offline; whole-document last-write destroys the losing device's accumulated progress. Per-field merges preserve both sides' facts.

Why must merge rules be identical in the web and Android code?

Sync is a two-party protocol — if each side merges differently, repeated syncs can oscillate or silently drop data depending on which device syncs last.

6 · Interview

Design sync for an offline-first app. What's your approach?

Store per-user state as one sync unit, merge per field by semantics (union for sets, max for monotonic counters, last-write for intent fields), keep the merge code identical across platforms, and test with divergent-device scenarios.

A field must support deletion in a union-merged set. How?

Tombstones: record deleted ids with timestamps in a removals set, and merge = (union of adds) minus (union of tombstones).
