Publishing Basics

From a debug APK to a Play Store listing real users can install

1. Release builds are a different artefact

▶ YouTube reference — the video for this lesson

What you run on your phone is a debug APK: unsigned, unoptimised, and installable only by a developer. What the Play Store distributes is an App Bundle — an AAB — built in release mode with code shrinking, resource shrinking and a signing key that proves the app came from you. Lose that signing key and you can never update the app again under the same listing, so it lives in a keystore backed up in two places, never committed to git. Play App Signing holds the final key on Google's side; you hold the upload key.

2. The listing is a product page

▶ YouTube reference — the video for this lesson

A store listing needs an icon, screenshots on real device sizes, a short description that says what the app does in one breath, and a full description for search. Add a privacy policy URL, a content rating questionnaire, and the data safety section declaring what the app collects — for Skillzify, that means Firebase Auth identifiers and Firestore progress data. The data safety form is a legal statement, not marketing copy: get it wrong and the listing can be removed.

3. Test tracks before production

▶ YouTube reference — the video for this lesson

Never ship straight to production. Internal testing goes to your own team, closed testing to a list of real users, open testing to anyone who opts in — each a chance to catch crashes on devices you do not own. Google reviews every production release, usually within days, checking policy compliance and basic function. Staged rollouts then limit the blast radius: release to 10 percent, watch crash rates and reviews, and only then go to 100 percent.

▸ Code example — see the Code section below.

Version codes only go up, and a published version can never be unpublished into the same code — every release is a commitment.

5 · Check

Say your answer out loud first, then reveal. Mark “I knew it” for +5 XP each.

Why is the signing key the most important file in a release?

Without it you cannot publish updates under the same listing. Lose it and the app is effectively orphaned.

Why ship to a closed test track before production?

Real users on real devices find crashes and policy issues you cannot, and a staged rollout limits the damage if something still slips through.

6 · Interview

AAB vs APK — why does Google prefer bundles?

An AAB lets Google generate optimised APKs per device — only the needed screen densities and CPU architectures — so users download less.

Your release is rejected in review. What do you do first?

Read the rejection reason exactly, fix the policy issue — often the data safety form or a permission — and resubmit. Never resubmit unchanged hoping for a different reviewer.
