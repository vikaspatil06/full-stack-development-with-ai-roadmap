Sliding Window Pattern

Expand, shrink, never look back

1. What a window is

▶ YouTube reference — the video for this lesson

A sliding window is a contiguous subarray or substring defined by two pointers, left and right, that only ever move forward. Instead of recomputing everything for each subarray — the O(n²) brute force — you maintain a running value as elements enter at the right and leave at the left. Each element enters once and leaves once, so the whole scan is O(n). The pattern fits any problem asking for the longest, shortest, or count of contiguous segments satisfying a condition.

2. Fixed windows: size k never changes

▶ YouTube reference — the video for this lesson

In a fixed window the size is given: maximum sum of any k consecutive elements, or the average of every window of size k. The template is mechanical — build the first window's sum, record the answer, then slide: add the entering element, subtract the leaving one, record again. The classic bug is an off-by-one in the first window, so build it in its own loop before sliding, and test with k equal to the array length and k equal to 1.

3. Variable windows: grow until it breaks, then shrink

▶ YouTube reference — the video for this lesson

In a variable window the size is the answer, not the input. The right pointer expands one step at a time, adding the new element to the window's state; while the condition is violated — a duplicate character, a sum too large, too many distinct values — the left pointer shrinks, removing elements until the condition holds again. Record the answer at the moment the window is valid: after shrinking for longest problems, and while valid for shortest ones. Stating exactly when you record is half the correctness argument.

4. The template and its limits

▶ YouTube reference — the video for this lesson

Memorise the skeleton below: expand, update state, shrink while invalid, record. The state is usually a sum, a frequency map, or a count of distinct values. The pattern needs the condition to be monotonic — shrinking must reliably restore validity — which is why it fails on arrays with negative numbers for sum conditions: removing an element might increase the sum, so the window logic breaks and prefix sums with a map take over instead. Recognising that boundary is as important as knowing the template.

def longest_at_most_k_distinct(s, k):
    counts = {}
    left = best = 0
    for right, ch in enumerate(s):
        counts[ch] = counts.get(ch, 0) + 1
        while len(counts) > k:
            old = s[left]
            counts[old] -= 1
            if counts[old] == 0:
                del counts[old]
            left += 1
        best = max(best, right - left + 1)
    return best

# Expand right, shrink left while invalid: each index moves once, O(n).

Why is the sliding window O(n) rather than O(n²)?

Each element enters the window once and leaves once, because both pointers only move forward. Total pointer movement is 2n, not n².

How do fixed and variable windows differ in structure?

A fixed window has a given size k and slides by adding one element and removing one. A variable window grows and shrinks by a condition, and its size is part of the answer.

In a longest-window problem, when do you record the answer?

After shrinking, when the window is valid again — recording while invalid would count windows that break the condition.

Why does the window fail for subarray-sum problems with negative numbers?

Shrinking no longer reliably restores validity, because removing a negative element increases the sum. The monotonicity the pattern needs is gone; use prefix sums with a map.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “Sliding window”?

Two forward-only pointers defining a contiguous segment, maintained with running state so each element is processed once — O(n).

What is “Fixed window”?

A window of given size k that slides by adding the entering element and removing the leaving one.

What is “Variable window”?

A window that expands and shrinks by a validity condition; its size is part of the answer.

What is “Window invariant”?

A statement of what the window contains and when the answer is recorded — the key to writing the shrink loop correctly.

What is “Monotonic condition”?

A condition where shrinking always moves toward validity; required for the window pattern to work.

What is “Frequency map state”?

A count map of what is inside the window, the usual state for distinct-count and anagram window problems.

7 · Interview ▾

How do you recognise a sliding-window problem?

It asks for the longest, shortest or count of contiguous subarrays or substrings satisfying a condition, and the condition is monotonic — shrinking the window can only help restore it.

Walk me through Minimum Window Substring at a high level.

Expand right until the window contains all required characters with enough counts, then shrink left as far as possible while it stays valid, recording the smallest valid window. Two frequency maps track need versus have.
