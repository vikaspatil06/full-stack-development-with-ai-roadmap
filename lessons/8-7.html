Services, health checks, env vars, and surviving the free tier

1. What Render actually runs

▶ YouTube reference — the video for this lesson

Render takes your repository and runs it as a service: it checks out the code, runs your build command, then runs your start command and keeps the process alive. A web service gets a public URL and a port from the environment — your server must listen on process.env.PORT, not a hardcoded number, or Render cannot route traffic to it. Environment variables hold the secrets: the Gemini key, the Firebase config, the daily cap — set in the dashboard, never in the repo, and changed without a redeploy of code.

2. Health checks and logs are your eyes

▶ YouTube reference — the video for this lesson

A health check is an endpoint Render pings to decide whether your service is alive — usually a small route that returns OK. If it fails, Render restarts the service; if deploys keep failing the check, the old version stays live instead of a broken new one. Logs stream every deploy and every runtime line, and they are the first place to look when the tutor stops answering: a failed build, a missing env var, a crash loop — each leaves a distinct signature in the log.

3. The free tier's honest limits

▶ YouTube reference — the video for this lesson

Free Render services spin down after inactivity, and the first request after sleep takes up to a minute to wake the service. That is acceptable for a staging deployment and a known trade-off, not a bug to chase — the fix is a paid plan or a keep-alive ping, and the right answer depends on who is waiting. Blueprint files (render.yaml) declare the whole setup as code, so the staging service can be recreated exactly instead of remembered from dashboard clicks.

▸ Code example — see the Code section below.

Render's deployment model is the reason Skillzify's staging deploys are manual: the dashboard button is the human gate between a green CI run and real users.

4 · Code ▾

▶ Run works for JavaScript snippets below — it runs in a sandboxed worker with a 2-second timeout. Python, HTML and CSS snippets are read-only here.

# render.yaml — the staging service, declared as code
services:
  - type: web
    name: skillzify-v2-staging
    env: node
    plan: free
    buildCommand: npm ci
    startCommand: node server.js
    healthCheckPath: /health
    envVars:
      - key: GEMINI_API_KEY
        sync: false # set in the dashboard, never in git

Why must your server listen on process.env.PORT instead of a fixed port?

Render assigns the port at runtime. A hardcoded port means Render cannot route traffic to your service.

What does a failing health check cause Render to do?

Restart the service, and keep the previous working version live instead of deploying the broken one.

7 · Interview ▾

Your free-tier service takes a minute to answer the first request of the day. What is happening?

It spun down from inactivity and is cold-starting. The fix is a paid plan or a keep-alive ping — a trade-off, not a bug.

Why declare infrastructure in render.yaml instead of clicking in the dashboard?

It is versioned, reviewable and recreatable: the service can be rebuilt exactly from git instead of from someone's memory of dashboard settings.
