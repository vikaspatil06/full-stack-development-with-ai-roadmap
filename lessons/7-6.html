Routes, arguments, deep links, and a back stack that behaves

1. Navigation is a graph of routes

▶ YouTube reference — the video for this lesson

Compose Navigation models an app as a graph: destinations are routes — strings like lesson/{lessonId} — and the NavHost renders the current destination while the back stack remembers where you came from. Arguments travel in the route itself, so a lesson screen receives its ID from the route and loads its data from the ViewModel. Type-safe navigation wraps those strings in serializable route classes, so a missing argument becomes a compile error instead of a runtime crash on a user's phone.

2. Deep links: the outside world enters at any screen

▶ YouTube reference — the video for this lesson

A deep link is a URL that opens a specific screen — a shared lesson link that opens the lesson directly instead of the home screen. You declare the URI pattern on the destination, and the system delivers the arguments the same way a manual navigation would. The discipline is making every destination work standalone: a lesson screen opened from a link must load its data from the ID alone, not depend on state set by the previous screen. That constraint improves the whole app, because every screen becomes independently loadable.

3. The back stack is a user promise

▶ YouTube reference — the video for this lesson

Users expect Back to undo navigation, not to exit the app unexpectedly or loop forever. Manage the stack deliberately: popUpTo when a login flow completes so Back never returns to the login screen, launchSingleTop so tapping the same bottom-nav item does not stack duplicates, and saveState so returning to a tab restores its scroll position. Nested graphs group related destinations — the whole auth flow, the whole lesson flow — so a single popUpTo can clear an entire section.

3 · Code

@Serializable data class LessonRoute(val lessonId: String)

NavHost(navController, startDestination = HomeRoute) {
  composable<HomeRoute> { HomeScreen(onLesson = { id ->
    navController.navigate(LessonRoute(id)) }) }
  composable<LessonRoute> { backStackEntry ->
    val route = backStackEntry.toRoute<LessonRoute>()
    LessonScreen(lessonId = route.lessonId)
  }
}
// Deep link: add a navDeepLink to LessonRoute for lesson URLs.

Why should a screen opened by a deep link load its data from the route argument alone?

Because no previous screen ran to set up state. The route argument is the only guaranteed input, so the screen must be independently loadable.

What do popUpTo and launchSingleTop prevent?

popUpTo clears destinations so Back never returns to a completed flow like login; launchSingleTop stops duplicate copies of the same screen stacking up.

6 · Interview

When would you use a nested navigation graph?

To group a flow — auth, onboarding, lessons — so one popUpTo clears the whole section and the graph reads as a feature, not a flat list of screens.

Type-safe routes vs string routes — what breaks with strings?

A typo or missing argument compiles fine and crashes at runtime. Typed routes make the compiler check destinations and arguments.
