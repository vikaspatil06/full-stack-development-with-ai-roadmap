Browser Rendering & the Critical Rendering Path

From HTML text to painted pixels

Goal — by the end of this lessonBy the end you can trace the critical rendering path — DOM, CSSOM, render tree, layout, paint — and explain what makes a page render slowly.

1. The critical rendering path

▶ YouTube reference — the video for this lesson

Rendering has five stages. The browser parses HTML into the DOM tree and CSS into the CSSOM tree. It combines them into a render tree containing only visible elements with their computed styles. Then layout computes the exact position and size of every box, and paint fills in pixels. JavaScript can force extra rounds of this work, which is why where scripts sit matters.

2. What blocks rendering

▶ YouTube reference — the video for this lesson

CSS in the head blocks rendering until it is parsed, because painting without styles would flash unstyled content. Classic scripts block parsing while they download and run. That is the whole reason Skillzify loads its stylesheet in the head and its scripts at the end of the body: styles first so the first paint is correct, scripts last so content appears fast.

▸ Code example — see the Code section below.

3. Layout thrashing and repaints

▶ YouTube reference — the video for this lesson

Reading a layout value like offsetHeight right after changing a style forces the browser to recalculate layout immediately — do that in a loop and the page stutters. Batch your reads, batch your writes, and prefer transform and opacity for animations because they skip layout and paint entirely, running on the compositor instead.

4. Measuring, not guessing

▶ YouTube reference — the video for this lesson

DevTools Performance records a page load frame by frame, and Lighthouse scores the experience. The metrics that matter are first paint, largest contentful paint, and interaction delay. Optimise the critical path — fewer blocking resources, smaller CSS, deferred scripts — and all three improve together.

Why does CSS block rendering but images do not?

The browser needs the full CSSOM before it can compute styles for the render tree; images are just boxes with a size until they arrive, so painting can start without them.

Why are transform and opacity the cheapest properties to animate?

They run on the compositor thread and skip layout and paint — the browser just moves an already-painted layer.

6 · Interview

Explain the critical rendering path in order.

Parse HTML into the DOM, parse CSS into the CSSOM, combine into the render tree, run layout to compute geometry, then paint pixels — with JS able to trigger extra rounds.

What is layout thrashing?

Alternating style writes and layout reads in a loop, forcing the browser to recalculate layout on every iteration instead of once.
