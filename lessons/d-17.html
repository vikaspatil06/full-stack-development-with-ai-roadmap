Tries & Prefix Trees

A tree where the path is the word

1. The node structure: characters on edges, words on paths

▶ YouTube reference — the video for this lesson

A trie (pronounced try, from retrieval) stores strings as paths through a tree. Each node holds a map from character to child node, plus a flag marking whether a complete word ends here. The root represents the empty prefix; following edges spells a string one character at a time. Words sharing a prefix share the path for that prefix, so storing cat, car and card costs one shared ca branch, not three separate strings. That sharing is the entire point of the structure.

2. Insert, search and prefix: three walks

▶ YouTube reference — the video for this lesson

All three operations are the same walk with different endings. Insert follows or creates a node per character, then sets the end-of-word flag. Search follows existing nodes and checks the flag at the end — a path that exists without the flag is a prefix, not a word. Prefix search (startsWith) follows the nodes and returns true if the path exists at all. Each costs O(L) for a word of length L, independent of how many words the trie holds — the property that makes tries shine as dictionaries grow.

3. Autocomplete: the killer application

▶ YouTube reference — the video for this lesson

Autocomplete is a prefix walk followed by a subtree harvest: walk to the node for the typed prefix, then depth-first collect every word in its subtree, stopping at the end-of-word flags. Search engines, IDEs and phone keyboards all run this exact algorithm. The same structure powers spell-checking, IP routing tables and word-game solvers: Word Search II builds a trie of the dictionary words and prunes the board search the moment the current path is not a prefix of any word, which is what makes it tractable.

4. Trie versus hash map: the honest trade-off

▶ YouTube reference — the video for this lesson

A hash set answers exact membership in average O(L) too — hashing the whole string — and uses less memory per word. The trie wins wherever prefixes matter: autocomplete, prefix counts, longest-common-prefix queries, and sorted iteration, none of which a hash map can do without scanning everything. The trie loses on memory, because each node carries a child map, and on cache behaviour. The interview answer names the question type: exact lookup only, use a hash set; anything about prefixes, use a trie.

class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()
            node = node.children[ch]
        node.is_end = True

    def _walk(self, prefix):
        node = self.root
        for ch in prefix:
            if ch not in node.children:
                return None
            node = node.children[ch]
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.is_end

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

Why does search need the end-of-word flag if the path exists?

A path can exist as a prefix of longer words without being a word itself. The flag distinguishes a stored word from a mere prefix.

What is the time complexity of trie search, and what does it depend on?

O(L) where L is the length of the word — it depends only on the word, not on how many words the trie contains.

How does autocomplete work on a trie?

Walk to the node for the typed prefix, then depth-first collect every complete word in that subtree, using the end-of-word flags.

When is a hash set better than a trie?

For exact membership only: it uses less memory and hashes the whole string in one step. A trie earns its cost when prefixes, ordering or prefix counts matter.

What is “Trie”?

A tree storing strings as character paths, where words sharing a prefix share nodes — built for prefix queries.

What is “Trie node”?

A node holding a map from character to child node plus an end-of-word flag.

What is “End-of-word flag”?

Marks that a complete stored word ends at this node, distinguishing words from mere prefixes.

What is “Prefix query”?

Checking whether any stored word starts with a given string — a single walk down the trie.

What is “Autocomplete”?

Walking to a prefix node and collecting all complete words in its subtree.

What is “Trie vs hash set”?

Hash sets win exact lookup on memory; tries win anything involving prefixes, ordering or prefix counts.

7 · Interview ▾

Design autocomplete for a search box. What structure and why?

A trie: insert all terms, then for each typed prefix walk to its node and collect the words in its subtree. Lookup cost depends on prefix length, not dictionary size.

How does a trie make Word Search II tractable?

Build a trie of all dictionary words, then DFS the board following trie edges — any path that is not a prefix of some word is pruned immediately instead of explored.
