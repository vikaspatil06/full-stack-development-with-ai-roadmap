HTML Base 2 — Tables, Forms, Inputs, Semantic Layout

Data on a page and data from the user

Goal — by the end of this lessonBy the end you can build a table, a working form with the right input types, and a page laid out with semantic tags instead of divs everywhere.

1. Tables for tabular data

▶ YouTube reference — the video for this lesson

Tables are for data with rows and columns, never for layout. A table uses table, thead for the header row, tbody for the body, tr for each row, and th for header cells and td for data cells. Skillzify uses tables in reference pages where comparing values side by side is the whole point.

2. Forms collect user input

▶ YouTube reference — the video for this lesson

A form wraps inputs and a submit button. Each input needs a label linked by for and id, so clicking the label focuses the field and screen readers announce it. The right input type matters: email brings up the right mobile keyboard and validates format, number restricts to digits, password hides the text, and select and textarea cover choices and long text.

▸ Code example — see the Code section below.

3. Semantic layout

▶ YouTube reference — the video for this lesson

Replace generic divs with tags that mean something: header for the top, nav for links, main for the one main content area, section for themed chunks, article for self-contained pieces, and footer for the close. Skillzify pages use exactly this skeleton, which is why its shared nav can be injected into one placeholder on every page.

4. Built-in validation

▶ YouTube reference — the video for this lesson

Attributes like required, minlength, min and max give you free validation before JavaScript ever runs. The browser blocks submission and shows a message. Never rely on it alone, though: real validation always happens again on the server.

3 · Code

<form action="/api/signup" method="post">
  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>
  <label for="level">Level</label>
  <select id="level" name="level">
    <option>Beginner</option><option>Intermediate</option>
  </select>
  <button type="submit">Create account</button>
</form>

Why link a label to its input with for and id?

Clicking the label focuses the field, and screen readers announce the label when the field is focused — without it, the field is unnamed to assistive tech.

Why is browser form validation not enough on its own?

Anyone can bypass the browser with curl or DevTools, so the server must validate every field again. Browser validation is only a convenience.

6 · Interview

When should you use a table, and when should you not?

Use tables for genuinely tabular data like scores or schedules. Never use them for page layout — that job belongs to Flexbox and Grid.

What is the difference between GET and POST on a form?

GET puts data in the URL and is for safe reads; POST puts data in the body and is for actions that change something, like signup or login.
