Strings & Hashing

Hash maps turn O(n²) into O(n)

1. Strings are immutable arrays of characters

▶ YouTube reference — the video for this lesson

In most languages a string cannot be changed in place: every concatenation builds a new string, so building a result with += inside a loop costs O(n²). The fix is to collect pieces in a list and join them once, which is O(n). The same immutability makes strings hashable and safe as dictionary keys, which is exactly why the hashing patterns in this lesson work. Treat a string as an array of characters with a few extra operations, and its behaviour stops being surprising.

2. Hashing: the frequency-map habit

▶ YouTube reference — the video for this lesson

A hash map stores key-value pairs with average O(1) lookup, and the frequency map is its most-used interview form: one pass to count characters or numbers, then answer any question about duplicates, anagrams or complements from the counts. Two Sum is the canonical example — for each number, check whether its complement is already in the map. The habit to build is asking, whenever you see a nested loop, whether a map could remember what the inner loop is searching for.

3. Anagrams, grouping, and the two-sum trick

▶ YouTube reference — the video for this lesson

Two strings are anagrams when their character counts match, so the signature of a string — its sorted form or its 26-count tuple — becomes a hash-map key that groups anagrams together. The same complement trick from Two Sum generalises: any problem asking whether a pair or group satisfies a condition is a candidate for one pass plus a map. Watch the key choice, though: using a sorted string as a key costs O(k log k) per word, while a count tuple is O(k).

4. Sliding window on strings

▶ YouTube reference — the video for this lesson

When a problem asks for the longest or smallest substring satisfying a condition, the window is the pattern: a right pointer expands, a left pointer shrinks when the condition breaks, and a map tracks what is inside. Longest substring without repeats is the template — expand until a duplicate appears, then move left past the previous occurrence. The window never moves backwards, so the whole scan is O(n), and the only state you maintain is the map and the best answer seen.

def longest_unique(s):
    seen = {}
    left = best = 0
    for right, ch in enumerate(s):
        if ch in seen and seen[ch] >= left:
            left = seen[ch] + 1
        seen[ch] = right
        best = max(best, right - left + 1)
    return best

# Sliding window + last-seen map: O(n) time, O(1) space for ASCII.

Why is building a string with += in a loop O(n²)?

Strings are immutable, so each += copies the whole string built so far. Collect pieces in a list and join once for O(n).

In the sliding-window template, why does the left pointer never move backwards?

The window only grows or slides forward, so each character enters and leaves the window once — that is what makes the scan O(n).

7 · Interview ▾

How would you check whether two strings are anagrams in O(n)?

Count characters of the first string in a frequency map, subtract the second string's counts, and check every count is zero — or compare 26-length count arrays. Sorting also works but costs O(n log n).

When is a hash map the wrong tool?

When order matters, when you need the minimum or maximum key, or when memory is tight — a sorted structure or two pointers may fit better despite the O(log n) lookup.
