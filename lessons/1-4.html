1. JavaScript waits without freezing

▶ YouTube reference — the video for this lesson

Network calls take time — a Gemini request can take seconds. JavaScript is single-threaded, so it cannot sit and wait; instead it registers work, keeps the page responsive, and comes back when the answer arrives. The modern spelling of that pattern is a Promise: an object representing a value that will exist later, which either resolves (success) or rejects (failure).

2. async/await: promises that read like normal code

▶ YouTube reference — the video for this lesson

▸ Code example — see the Code section below.

Three details matter. First, fetch only rejects on network failure — an HTTP 500 still resolves, so you must check res.ok yourself. Second, request and response bodies are JSON strings; JSON.stringify and res.json() are the two conversion points. Third, every async call needs a failure path the user can survive — Skillzify's AI UI shows a friendly fallback instead of a frozen spinner.

3. Race conditions

▶ YouTube reference — the video for this lesson

If a learner taps "hint" twice quickly, two requests fly; the slower first response can arrive after the second and overwrite newer state. Fixes range from disabling the button while loading, to tagging requests with an incrementing ID and ignoring stale replies. Knowing the bug exists puts you ahead of most tutorial code, which never mentions it.

How Skillzify uses thissync.js pushes progress to Firestore and ai.js calls the backend — both are this exact pattern: await, check, parse, and a catch that degrades gracefully (keep working offline; show a fallback message).
Watch out — common mistakes
  • Forgetting that fetch resolves on HTTP errors — always check res.ok.
  • Firing duplicate requests on double-clicks with no guard, creating race conditions.

4 · Code ▾

▶ Run works for JavaScript snippets below — it runs in a sandboxed worker with a 2-second timeout. Python, HTML and CSS snippets are read-only here.

async function askTutor(question) {
  try {
    const res = await fetch("/api/tutor", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ question })
    });
    if (!res.ok) throw new Error("Server said " + res.status);
    const data = await res.json();
    return data.reply;
  } catch (err) {
    return "Tutor unavailable — try again.";
  }
}

fetch() resolves even when the server returns HTTP 500 — so what must you check?

res.ok (or res.status). fetch only rejects on network-level failures, not HTTP error statuses.

What is a race condition in async UI code?

Two overlapping async operations complete out of order, so a stale earlier result overwrites a newer one; fixed by disabling triggers, request IDs, or cancellation.

7 · Interview ▾

Explain Promises and async/await.

A Promise represents a future value that resolves or rejects; async/await is syntax that lets you write that flow sequentially with try/catch error handling.

How do you handle errors from an API call in UI code?

Check res.ok, parse defensively, catch network failures, and give the user a fallback state — never a frozen spinner or a crash.
