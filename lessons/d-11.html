States, choices, recurrence — DP is recursion with memory

1. Recognising DP: overlapping subproblems, optimal substructure

▶ YouTube reference — the video for this lesson

DP applies when a problem breaks into subproblems that repeat and the optimal answer is built from optimal answers to those subproblems. Fibonacci repeats fib(3) many times; Climbing Stairs reuses the ways to reach each step; Coin Change reuses the best answer for every smaller amount. The test is to draw the recursion tree and look for repeated nodes. If the same subproblem appears twice, memoisation will help; if the optimal answer needs optimal sub-answers, DP is the right frame.

2. The five-step method

▶ YouTube reference — the video for this lesson

Never code DP by feel. First, define the state in words — what dp[i] means. Second, list the choices at that state. Third, write the recurrence: dp[i] in terms of smaller states. Fourth, set the base cases. Fifth, decide the order to fill the table. Climbing Stairs is the template: dp[i] is the ways to reach step i, the choices are one or two steps, so dp[i] = dp[i−1] + dp[i−2], with dp[0] = dp[1] = 1. Saying the state aloud before coding is what separates a DP solution from a lucky guess.

3. Memoisation versus tabulation

▶ YouTube reference — the video for this lesson

Memoisation is top-down: write the natural recursion, cache each result, and let the call stack drive the order. Tabulation is bottom-up: fill a table in increasing order, no recursion involved. Memoisation is faster to write and only computes needed states; tabulation avoids stack limits and usually compresses space — Climbing Stairs needs only the previous two values, not the whole table. In interviews, start with memoisation to get the recurrence right, then convert to tabulation if space matters.

4. The classic pattern families

▶ YouTube reference — the video for this lesson

Most DP problems fall into a few families. One-dimensional DP: climbing stairs, house robber, coin change. Grid DP: unique paths, minimum path sum. Subsequence DP: longest increasing subsequence, longest common subsequence, edit distance. Knapsack DP: partition a set under a sum constraint. Each family has one canonical problem; learn it deeply and the rest are variations in state and choice. When stuck on a new DP problem, ask which family it resembles and what its state would be.

def climb_stairs(n):
    if n <= 1:
        return 1
    prev2, prev1 = 1, 1
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, prev1 + prev2
    return prev1

# dp[i] = dp[i-1] + dp[i-2]; two variables compress the table to O(1) space.

What two properties must a problem have for DP to apply?

Overlapping subproblems — the same subproblem recurs — and optimal substructure — the optimal answer is built from optimal answers to subproblems.

Why can Climbing Stairs run in O(1) space?

Each state depends only on the previous two, so the full table is unnecessary — two variables carry everything forward.

7 · Interview ▾

How do you approach a DP problem you have never seen?

Define the state in words, list the choices, write the recurrence, set base cases, then code memoised recursion first and convert to tabulation only if needed.

What is the difference between memoisation and tabulation?

Memoisation is top-down recursion with a cache; tabulation is bottom-up table filling. Same recurrence, different order — tabulation avoids recursion depth and usually compresses space.
