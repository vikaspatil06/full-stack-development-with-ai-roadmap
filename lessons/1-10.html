DOM Deep — Building & Updating UI Without a Framework

The manual rendering React automates

1. Building elements: createElement versus innerHTML

▶ YouTube reference — the video for this lesson

There are two ways to put markup on a page. innerHTML parses a string of HTML — fast to write, but dangerous with untrusted data because injected markup runs as real HTML, which is the classic cross-site scripting hole. createElement builds nodes one by one and sets text with textContent, which can never be interpreted as markup. The professional rule: use template strings with innerHTML only for markup you fully control, and textContent for anything a user typed. Skillzify renders lesson titles and user content through safe paths for exactly this reason.

2. Templates and fragments: build once, insert once

▶ YouTube reference — the video for this lesson

Appending elements to the live DOM one at a time forces the browser to recalculate layout repeatedly. A DocumentFragment is an off-screen container: build the whole list inside it, then append the fragment once, and the browser does a single layout pass. The template element goes further — its content is inert markup you clone per item with cloneNode(true), fill in, and append. Together they are how vanilla code renders a 250-lesson list smoothly without a framework.

3. Event delegation: one listener, whole list

▶ YouTube reference — the video for this lesson

Attaching a click handler to every card in a list wastes memory and breaks the moment items are re-rendered. Delegation attaches one listener to the parent instead: clicks bubble up, and event.target.closest("[data-lesson-id]") finds which card was clicked. Items added later work automatically, because the listener lives on the parent that never changes. This is the pattern Skillzify's pages use for lesson lists, exercise cards and reference entries — one listener per list, whatever its size.

4. Re-rendering without destroying state

▶ YouTube reference — the video for this lesson

The naive re-render — wipe the container and rebuild everything — loses scroll position, focus, and any text typed into inputs. Efficient vanilla rendering updates surgically: change only the text or class that changed, reuse existing nodes keyed by id, and rebuild only the section whose data actually changed. dataset supports this by carrying ids and state on the elements themselves, readable in handlers without a parallel lookup table. Mastering this is understanding, by hand, the exact problem React's virtual DOM automates — which is why it makes framework behaviour predictable later.

4 · Code ▾

▶ Run works for JavaScript snippets below — it runs in a sandboxed worker with a 2-second timeout. Python, HTML and CSS snippets are read-only here.

const list = document.querySelector("#lessons");
const frag = document.createDocumentFragment();

for (const lesson of lessons) {
  const card = document.createElement("article");
  card.className = "card";
  card.dataset.lessonId = lesson.id;
  const title = document.createElement("h3");
  title.textContent = lesson.title;
  card.appendChild(title);
  frag.appendChild(card);
}
list.appendChild(frag);

list.addEventListener("click", (e) => {
  const card = e.target.closest("[data-lesson-id]");
  if (card) openLesson(card.dataset.lessonId);
});

Why is textContent safer than innerHTML for user data?

textContent inserts the value as pure text that is never parsed as markup, so injected tags cannot execute. innerHTML parses the string as HTML, which is the XSS hole.

What does a DocumentFragment buy you?

You build many nodes off-screen and insert them in one append, so the browser runs one layout pass instead of one per element.

Why does delegation keep working for items added later?

The listener is on the parent, and clicks bubble up from any child — including children created after the listener was attached.

What does a full wipe-and-rebuild re-render destroy?

Scroll position, focus, text typed into inputs, and any transient element state — which is why surgical updates are preferred.

Bonus round — flashcards (+5 XP each)

Define each term out loud before revealing. These count toward your score below.

What is “createElement”?

Building a DOM node programmatically, with textContent for safe text — the XSS-proof way to render user data.

What is “DocumentFragment”?

An off-screen container for building many nodes before a single insertion, avoiding repeated layout work.

What is “template element”?

Inert markup in the page that you clone per item, fill in, and append — a reusable node blueprint.

What is “Event delegation”?

One listener on a parent handling events from all children via bubbling and closest().

What is “dataset”?

The data-* attributes on an element, readable and writable in JavaScript — a place to carry ids and state on the node itself.

What is “Surgical update”?

Changing only the nodes whose data changed, preserving scroll, focus and input state instead of rebuilding the whole list.

7 · Interview ▾

Explain event delegation and when you would use it.

Attach one listener to a parent and use event bubbling plus closest() to identify the clicked child. Use it for lists and grids: fewer listeners, and dynamically added items work without rebinding.

How do you render a large list efficiently without a framework?

Build nodes in a DocumentFragment with createElement and textContent, insert once, delegate events on the parent, and update surgically by id instead of rebuilding everything.
