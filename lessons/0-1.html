How a Web Page Loads

From typing a URL to pixels on screen

Goal — by the end of this lessonBy the end you can trace exactly what happens between pressing Enter on a Skillzify URL and seeing the homepage — and explain why Skillzify's scripts sit at the bottom of the page.

1. The journey of one page load

▶ YouTube reference — the video for this lesson

When a browser opens https://skillzify-v2-staging.onrender.com, five things happen in order:

  • DNS lookup — the domain name is translated into the IP address of a Render server.
  • HTTP request — the browser asks that server for index.html. The server replies with the file's text. Nothing has been "run" yet — HTML is just text.
  • Parsing — the browser reads the HTML top to bottom and builds the DOM (Document Object Model): a live tree of elements it can draw and JavaScript can change.
  • CSS is fetched and parsed — a stylesheet link like assets/css/style.css?v=29 triggers another request. The parsed rules become the CSSOM. DOM + CSSOM together decide what gets painted.
  • JavaScript runs last — scripts execute in the order they appear, and each one can read and modify the DOM.

2. Why scripts go at the bottom

▶ YouTube reference — the video for this lesson

A classic script blocks parsing while it downloads and runs. Put a script in the head and the browser stops building the page until it finishes. Skillzify puts all its scripts just before the closing body tag, so the learner sees the page first and the behaviour arrives a moment later.

▸ Code example — see the Code section below.

Order matters because later files use helpers from earlier ones: auth.js and sync.js call the toast and storage helpers that app.js defines. Swap the order and the page breaks with "not a function" errors.

3. Cache-busting: the ?v=29 trick

▶ YouTube reference — the video for this lesson

Browsers cache CSS and JS aggressively. If you fix a bug in style.css but the learner's browser keeps the old cached copy, your fix never arrives. Skillzify appends a version query — style.css?v=29 — and bumps the number on every change. A new URL means a fresh download.

How Skillzify uses thisThere is no build step and no framework. You can run the entire site locally with one command — python3 -m http.server 8080 inside the project folder — because a page load really is just files being served.
Watch out — common mistakes
  • Putting scripts in the head and wondering why the page renders slowly — classic scripts block parsing.
  • Assuming a pushed file change reaches users instantly, ignoring browser caching (hence ?v=).

Why do Skillzify's scripts sit at the bottom of the page?

Classic scripts block HTML parsing while they download and run. At the bottom, the page content paints first and behaviour loads after.

What does style.css?v=29 do, and why does the number change?

It is cache-busting. The changed query string makes the URL new, so browsers download the fresh CSS instead of reusing a cached copy.

7 · Interview ▾

Walk me through what happens when I type your site's URL.

DNS resolves the domain, the browser requests index.html, parses it into the DOM, fetches CSS (CSSOM) and JS in order, then paints — with scripts at the bottom so content renders first.

Why does your site version its CSS/JS URLs?

Cache-busting: a changed query string creates a new URL, forcing browsers to fetch the updated file instead of a stale cached copy.
