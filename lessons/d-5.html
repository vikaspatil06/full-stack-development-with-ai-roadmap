Linked Lists

Pointers, not indexes — draw the arrows first

1. Nodes and pointers: why lists exist

▶ YouTube reference — the video for this lesson

A linked list is a chain of nodes, each holding a value and a pointer to the next node. Unlike an array, a list can grow and shrink by rewiring one pointer in O(1), but reaching the tenth node means walking nine pointers — random access is O(n). That trade-off is the whole story: lists win when you insert and delete at known positions, arrays win when you index. In interviews the list is rarely the end goal; it is the stage where pointer discipline is tested.

2. The dummy node trick

▶ YouTube reference — the video for this lesson

Most linked-list bugs live at the head: deleting the first node, merging from an empty list, or building a new list from scratch all need special cases. A dummy node sitting before the real head removes them — you always have a previous node, and the answer is dummy.next at the end. This one trick simplifies merge, remove-nth, and partition problems so much that reaching for it should be automatic. When a problem builds or rewrites a list, start with a dummy.

3. Fast and slow pointers

▶ YouTube reference — the video for this lesson

Two pointers moving at different speeds through a list detect structure that one pointer cannot see. A fast pointer moving two steps per slow pointer's one catches up exactly when there is a cycle, and when the fast pointer reaches the end, the slow pointer sits at the middle. The same idea finds the nth node from the end: advance fast by n, then move both together. The pattern is always the same — create a gap or a speed difference, then let the pointers meet.

4. Reversal: the interview rite of passage

▶ YouTube reference — the video for this lesson

Reversing a list in place is the most-asked linked-list operation because it tests whether you can hold three pointers in your head: previous, current, and next. The loop saves next, flips current.next to previous, then advances both — and the classic bug is losing next before the flip, which severs the list. Draw the arrows on paper before you type a line. If you can reverse a list cold, you can do almost any pointer surgery an interview will ask for.

def reverse_list(head):
    prev, curr = None, head
    while curr:
        nxt = curr.next
        curr.next = prev
        prev = curr
        curr = nxt
    return prev

# Three pointers, one flip per step: O(n) time, O(1) space.

Why does a dummy node simplify linked-list code?

It guarantees a previous node always exists, so head deletion, empty-list merges and building a new list need no special case — the answer is dummy.next.

How do fast and slow pointers detect a cycle?

The fast pointer moves two steps per slow step, so if there is a cycle it must eventually lap the slow pointer and meet it; on an acyclic list it reaches the end.

7 · Interview ▾

Reverse a linked list — and narrate what each pointer holds at each step.

Keep prev, curr and next. Save next, point curr.next at prev, advance prev to curr and curr to next. The list is never lost because next is saved before the flip.

Why would you choose a linked list over an array?

When insertions and deletions at known positions dominate, since rewiring one pointer is O(1) while an array shifts O(n) elements — at the cost of O(n) random access.
