Goal — by the end of this lessonBy the end you can navigate VS Code fluently, use its integrated terminal, install the extensions that matter, and run a local server for any web project.

1. The editor is the workshop

▶ YouTube reference — the video for this lesson

VS Code is where nearly all of this course happens. Learn its core moves: Ctrl+P to open any file by name, Ctrl+Shift+F to search the whole project, Ctrl+grave to toggle the terminal, and multi-cursor editing with Alt+Click. These four shortcuts alone save hours a week once they are muscle memory.

2. The integrated terminal

▶ YouTube reference — the video for this lesson

The terminal inside VS Code runs the same commands as a standalone one: node server.js starts a backend, python3 -m http.server 8080 serves a static site, git status checks your repo. Running the server from inside the editor keeps the code, the logs and the errors in one window.

▸ Code example — see the Code section below.

3. Extensions that earn their place

▶ YouTube reference — the video for this lesson

Install only extensions you will actually use: Python and Pylance for Python, ESLint and Prettier for JavaScript, Live Server for quick static previews, and GitLens for seeing who changed a line and when. Every extension costs startup time, so audit the list monthly and remove the ones you never open.

4. Running code locally, the habit

▶ YouTube reference — the video for this lesson

Every project in this course runs locally first: a static site on port 8080, a Node server on 3000, a Python script in the terminal. If it does not run on your machine, it does not ship — that discipline is what makes deployments boring instead of scary.

Why serve a static site over HTTP instead of opening the file directly?

File URLs block fetch, modules and some APIs for security; a local server behaves like production and avoids those restrictions.

What is the fastest way to open a file you know the name of?

Ctrl+P quick-open, then type a few letters of the filename — far faster than clicking through the folder tree.

7 · Interview ▾

What is the difference between the VS Code terminal and a separate terminal app?

Nothing fundamental — it is the same shell embedded in the editor. The advantage is context: it opens in the project folder with the editor beside it.

Why keep your extension list small?

Each extension adds startup time, memory and potential conflicts. A lean list keeps the editor fast and the tooling predictable.
