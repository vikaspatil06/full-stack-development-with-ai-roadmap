Recursion & Backtracking

Trust the recursion — define the base case, then the choice

1. Recursion is a call stack, not magic

▶ YouTube reference — the video for this lesson

A recursive function solves a smaller version of the same problem and trusts the result. Two things must be right: the base case, which stops the recursion, and the progress step, which guarantees the input shrinks toward it. Every call frame sits on the stack, so depth n costs O(n) space, and a missing base case is an infinite recursion that ends in a stack overflow. When you are stuck, write the base case first, then the recursive step for the smallest non-trivial input, and trace it by hand.

2. Backtracking: choose, explore, undo

▶ YouTube reference — the video for this lesson

Backtracking explores a decision tree depth-first: pick a candidate, recurse, then undo the pick so the next branch starts clean. That undo step is the whole pattern — forgetting it is the most common backtracking bug, and it produces answers polluted by earlier choices. The template is identical across subsets, permutations, combinations and word search; only the choice set and the validity check change. If you can write one backtracking solution cleanly, you can write them all.

3. The decision-tree mental model

▶ YouTube reference — the video for this lesson

Before coding, draw the tree: each level is one decision, each path from root to leaf is one candidate answer. Subsets branch include-or-exclude at each element, giving 2ⁿ leaves; permutations branch over the remaining elements, giving n! leaves. Counting the leaves first tells you the complexity and whether pruning is needed. This model also explains why backtracking is exponential by nature — you are enumerating candidates, not computing a formula.

4. Pruning and the complexity check

▶ YouTube reference — the video for this lesson

Pruning cuts branches that cannot lead to a valid answer, using a constraint check before recursing — for example, skipping duplicate values in Combination Sum by sorting first and ignoring repeats. Pruning never changes the worst case, but it decides whether a solution passes in practice. Always state the worst-case complexity honestly: O(2ⁿ) for subsets, O(n!) for permutations. If the constraints allow that, backtracking is the right tool; if not, you need memoisation or DP.

def subsets(nums):
    result, path = [], []
    def backtrack(i):
        if i == len(nums):
            result.append(path[:])
            return
        path.append(nums[i])
        backtrack(i + 1)
        path.pop()
        backtrack(i + 1)
    backtrack(0)
    return result

# Each element: include or exclude. 2^n leaves, O(n * 2^n) total work.

What are the two things a recursive function must get right?

A base case that stops the recursion, and a progress step that shrinks the input toward the base case on every call.

Why is the undo step essential in backtracking?

Each branch must start from the same state. Without undoing the choice, later branches inherit earlier picks and produce wrong answers.

7 · Interview ▾

How do you decide between recursion and iteration?

Recursion fits problems with a natural self-similar structure — trees, decision trees, divide and conquer. Iteration fits flat loops and avoids stack-depth limits; deep recursion can overflow the stack.

Your backtracking solution is too slow. What do you try first?

Prune invalid branches earlier, memoise repeated subproblems if they overlap, and check whether the problem has optimal substructure that allows DP instead of enumeration.
