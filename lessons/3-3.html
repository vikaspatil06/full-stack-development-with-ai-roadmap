1. Middleware is a chain of functions

▶ YouTube reference — the video for this lesson

In Express, a request passes through middleware functions in registration order. Each one receives req, res and next: it can read or modify the request, end the response early, or call next() to pass control onward. If a middleware never calls next() and never responds, the request hangs forever — the most common Express beginner bug.

2. Built-in and third-party middleware

▶ YouTube reference — the video for this lesson

express.json() parses JSON bodies into req.body, express.static() serves files from a folder, and helmet, cors and morgan add security headers, cross-origin rules and request logging. Skillzify's server.js composes these first, so every route below them already has a parsed body and a logged request.

3. Order is the whole game

▶ YouTube reference — the video for this lesson

Middleware runs in the order it is registered, and route handlers are just middleware that match a path and method. Put the JSON parser after your routes and req.body is undefined. Put an auth check after a public route and the route stays public. Read server.js top to bottom as a pipeline diagram, not a bag of functions.

4. Error middleware has four arguments

▶ YouTube reference — the video for this lesson

A middleware with four parameters (err, req, res, next) only runs when an error is passed to next(err) or thrown in an async handler. It is the last stop: log the error, hide internals, and send a consistent JSON error. One error handler for the whole server beats a try/catch pasted into every route.

3 · Code

function requireBody(req, res, next) {
  if (!req.body || typeof req.body.question !== "string") {
    return res.status(400).json({ error: "question is required" });
  }
  next();
}
app.use(express.json({ limit: "10kb" }));
app.post("/api/tutor", requireBody, function (req, res) {
  res.json({ reply: "Hello from the tutor" });
});

What happens if a middleware never calls next() and never sends a response?

The request hangs until the client times out. Every middleware must either respond or call next().

Why does middleware order matter?

Middleware runs in registration order, so a parser registered after a route never runs for it, and an auth check after a route leaves that route unprotected.

6 · Interview

Explain the Express middleware chain.

Requests pass through registered middleware in order; each can modify req/res, end the response, or call next() to continue. Error middleware takes four arguments and runs on next(err).

How do you handle errors in async Express handlers?

Catch them and pass to next(err), or use a wrapper that forwards rejections — otherwise the promise rejection is unhandled and the request hangs.
