Graphs (BFS/DFS)

Nodes, edges, visited set — every graph problem is a traversal

1. Modelling: everything is a graph if you look right

▶ YouTube reference — the video for this lesson

A graph is nodes connected by edges, and the first skill is recognising one: grid cells are nodes with four neighbours, courses are nodes with prerequisite edges, words are nodes linked by one-letter changes. The standard representation is an adjacency list — a map from each node to its neighbours — because it is O(V + E) in space and enumerates neighbours fast. Before coding any graph problem, write down what the nodes are, what the edges are, and whether edges are directed.

2. DFS versus BFS: depth or breadth

▶ YouTube reference — the video for this lesson

Depth-first search dives down one path before backtracking, using a stack or recursion; breadth-first search visits level by level using a queue. DFS is natural for exploring all paths, detecting cycles, and topological sorting. BFS is the tool when distance matters — it finds the shortest path in an unweighted graph because it reaches nodes in order of increasing distance. The algorithm is the same shape either way: pop a node, mark it visited, push its unvisited neighbours.

3. The visited set: the one bug that loops forever

▶ YouTube reference — the video for this lesson

Graphs have cycles, so a traversal without a visited set revisits nodes forever. Mark a node visited when you enqueue it, not when you dequeue it — marking late lets the same node enter the queue many times, which is the most common BFS bug. The visited set is also the answer in many problems: in Number of Islands, each unvisited land cell starts a new island, and the flood fill marks the whole island visited. If your graph code hangs, the visited set is the first suspect.

4. Classic patterns: islands, topo sort, multi-source BFS

▶ YouTube reference — the video for this lesson

Three patterns cover most graph interviews. Connected components: count the flood fills from unvisited nodes. Topological sort: order nodes so prerequisites come first, using DFS finishing times or Kahn's indegree algorithm — and a cycle means no valid order exists, which is the whole Course Schedule problem. Multi-source BFS: enqueue all sources at once, as in Rotting Oranges, and the level number is the minutes elapsed. Learn these three and most graph problems become variations.

from collections import deque

def bfs(grid, sr, sc):
    q = deque([(sr, sc)])
    grid[sr][sc] = '0'
    while q:
        r, c = q.popleft()
        for dr, dc in [(1, 0), (-1, 0), (0, 1), (0, -1)]:
            nr, nc = r + dr, c + dc
            if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
                if grid[nr][nc] == '1':
                    grid[nr][nc] = '0'
                    q.append((nr, nc))

# Flood fill from one island cell: O(cells) time, O(cells) queue space.

Why mark a node visited when you enqueue it, not when you dequeue it?

Marking late lets the same node be enqueued many times by different neighbours, blowing up the queue and the work; marking at enqueue time guarantees one entry per node.

Why does BFS find the shortest path in an unweighted graph?

It visits nodes in order of increasing distance from the source, so the first time a node is reached is via the shortest possible path.

7 · Interview ▾

How do you detect a cycle in a directed graph?

DFS with three states — unvisited, visiting, done. Reaching a node in the visiting state means a back edge, hence a cycle. A plain visited set is not enough for directed graphs.

When would you choose DFS over BFS?

When exploring all paths, detecting cycles, doing topological sort, or when memory matters — DFS uses O(h) stack space versus BFS's O(w) queue, which can be much larger.
