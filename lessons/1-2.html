Closures & Scope — Functions That Remember

Where variables live and how long they last

1. Scope is where a name is visible

▶ YouTube reference — the video for this lesson

JavaScript has global scope, function scope and block scope. A variable declared inside a block with let or const exists only in that block; a variable declared inside a function exists only in that function. Inner code can read outer variables, but outer code cannot read inner ones. This one-way visibility is lexical scope, decided by where the code is written, not where it runs.

2. A closure is a function plus its birthplace

▶ YouTube reference — the video for this lesson

When a function is created inside another function, it keeps a live reference to the outer function's variables even after the outer function has returned. That remembered environment is a closure. It is not a special feature you opt into — every function in JavaScript is a closure over the scope where it was defined.

3. Private state without classes

▶ YouTube reference — the video for this lesson

Closures create genuinely private variables: nothing outside can touch count except through the returned function. Skillzify uses this shape in app.js, where an IIFE wraps private helpers and exposes only a small public API on window.Skillzify. The same pattern powers counters, caches and rate limiters across the codebase.

4. The classic closure trap

▶ YouTube reference — the video for this lesson

Looping with var and creating callbacks inside the loop used to capture one shared variable, so every callback saw the final value. let fixes it because each iteration gets its own binding. When a bug smells like every handler doing the same thing, check whether a closure is sharing a variable you thought was per-item.

4 · Code ▾

▶ Run works for JavaScript snippets below — it runs in a sandboxed worker with a 2-second timeout. Python, HTML and CSS snippets are read-only here.

function makeCounter() {
  let count = 0;              // private: only the closure sees it
  return function () {
    count += 1;
    return count;
  };
}
const xpCounter = makeCounter();
xpCounter(); // 1
xpCounter(); // 2 — count survived between calls

What is a closure, in one sentence?

A function that retains access to the variables of the scope where it was created, even after that scope has finished executing.

Why does let fix the classic loop-closure bug but var does not?

let creates a fresh binding per loop iteration, so each callback captures its own value; var has one function-scoped binding shared by all callbacks.

7 · Interview ▾

How would you create private state in JavaScript without a class?

A closure: an outer function holds the variable and returns inner functions that read and update it; nothing outside can reach the variable directly.

Explain lexical scope vs dynamic scope.

Lexical scope resolves names by where code is written; dynamic scope would resolve by where it runs. JavaScript is lexical.
