LIFO and FIFO — the order is the algorithm

1. Stack: undo, matching, and nesting

▶ YouTube reference — the video for this lesson

A stack is last-in-first-out: push adds to the top, pop removes from the top, and peek reads it. That order is exactly what nested structures need — an opening bracket waits on the stack until its closing bracket arrives, and an undo history replays in reverse. Valid Parentheses is the purest form: push opens, match-and-pop closes, and anything left over means imbalance. Whenever a problem involves nesting, reversal, or most-recent-first processing, reach for the stack before anything else.

2. The monotonic stack pattern

▶ YouTube reference — the video for this lesson

A monotonic stack keeps its elements in increasing or decreasing order, popping anything that breaks the order. It answers next-greater-element questions in O(n): each element is pushed once and popped once, and the pop reveals the next greater element for everything removed. Daily Temperatures is the same shape — the stack holds indices waiting for a warmer day. The recognition cue is a problem asking for the next element that is bigger or smaller than the current one.

3. Queues and breadth-first thinking

▶ YouTube reference — the video for this lesson

A queue is first-in-first-out: enqueue at the back, dequeue from the front. It is the order of fairness — tasks processed in arrival order — and the engine of breadth-first search, which visits nodes level by level. A double-ended queue, or deque, allows both ends and powers sliding-window maximum, where the deque holds candidates in decreasing order. Knowing which end each operation touches is the difference between a queue and a stack.

4. Designing with stacks and queues

▶ YouTube reference — the video for this lesson

Min Stack shows how to extend a stack: store each value alongside the minimum so far, and getMin becomes O(1). Implementing a queue with two stacks shows the deeper idea — one stack for input, one for output, with a transfer that reverses order exactly once per element, giving amortised O(1) operations. Interviewers love these design problems because they test whether you understand the order, not just the API.

def is_valid(s):
    stack = []
    pairs = {')': '(', ']': '[', '}': '{'}
    for ch in s:
        if ch in '([{':
            stack.append(ch)
        elif not stack or stack.pop() != pairs[ch]:
            return False
    return not stack

# Push opens, match-and-pop closes: O(n) time, O(n) space.

Why does Valid Parentheses need a stack rather than just counting brackets?

Counting cannot check order or type — '([)]' has balanced counts but wrong nesting. A stack matches each closer with the most recent opener.

In a monotonic stack, why is each element pushed and popped at most once?

Once popped, an element never returns, so total pushes and pops across the whole run are O(n) — that is why the algorithm is linear.

7 · Interview ▾

Design a stack that returns the minimum in O(1).

Store each pushed value together with the minimum so far, or keep a parallel min-stack. getMin then reads the top of the min-stack in O(1).

How do you implement a queue using two stacks?

Push into the input stack; to dequeue, move everything to the output stack if it is empty, which reverses order. Each element moves at most twice, so operations are amortised O(1).
