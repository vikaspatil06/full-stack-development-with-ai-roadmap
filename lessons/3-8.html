Goal — by the end of this lessonBy the end you can test any API with Postman and curl, write a small automated API test, and explain why testing the API first saves frontend debugging time.

1. Test the API before the UI

▶ YouTube reference — the video for this lesson

When a feature breaks, the first question is whether the API or the frontend is at fault. Testing the endpoint directly answers it in seconds. Postman gives you a visual way to build requests, save them into collections, and share them; curl does the same from the terminal and in scripts. Both beat guessing from a broken UI.

2. A request is method, URL, headers, body

▶ YouTube reference — the video for this lesson

Every API call is four things: the method, the URL with any path or query parameters, headers like Content-Type and Authorization, and the body. Set each deliberately in Postman, save the request, and you have a regression check you can re-run after every server change. Skillzify's tutor endpoint is one saved request away from a full test.

▸ Code example — see the Code section below.

3. What to check on every endpoint

▶ YouTube reference — the video for this lesson

Happy path returns the right status and shape. Missing fields return 400. Bad auth returns 401. Too many requests return 429. An oversized body is rejected. Each of these is a one-line test in Postman or a script, and together they form a contract the frontend can rely on.

4. From manual to automated

▶ YouTube reference — the video for this lesson

Postman collections can run as a suite with assertions on status and body, and the same checks can live as automated tests using a library like supertest against the Express app. Manual testing finds bugs once; automated tests find them every time the code changes.

3 · Code

# Health check
curl http://localhost:3000/api/health
# Tutor call with a JSON body
curl -X POST http://localhost:3000/api/tutor \
  -H "Content-Type: application/json" \
  -d '{"question": "What is a closure?"}'
# Same call, show headers and status
curl -i -X POST http://localhost:3000/api/tutor \
  -H "Content-Type: application/json" \
  -d '{}'

Why test an API directly instead of only through the frontend?

It isolates the fault: if the endpoint works in Postman but not in the UI, the bug is in the frontend; if it fails in Postman too, it is the server.

What four things define an API request?

Method, URL, headers, and body. Getting any one wrong is the most common cause of a failing call.

6 · Interview

How do you test a rate-limited endpoint?

Send requests until the limit fires and confirm a 429 with the right message, then confirm requests succeed again after the window resets.

What is the difference between manual API testing and automated API tests?

Manual testing in Postman or curl finds a bug once; automated tests run the same checks on every change, so regressions are caught immediately.
