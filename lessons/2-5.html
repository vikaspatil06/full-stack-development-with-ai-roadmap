1. Comprehensions: collections in one line

▶ YouTube reference — the video for this lesson

A comprehension builds a collection from another iterable with an optional filter, reading like a sentence: squares of the numbers that are even. List, dict and set comprehensions all exist. They replace the two-line pattern of creating an empty collection and appending in a loop — the single most common Python idiom, and the one Skillzify's flowchart code uses to transform parsed nodes.

2. When not to use them

▶ YouTube reference — the video for this lesson

A comprehension with nested loops and two conditions stops being readable and becomes a puzzle. If the logic needs several statements, side effects, or error handling, a plain loop is the honest choice. Readability is the test, not brevity.

3. Decorators wrap functions

▶ YouTube reference — the video for this lesson

A decorator is a function that takes a function and returns a new one with added behaviour — timing, logging, caching, access checks — without touching the original code. The @ syntax applies it at definition. The wrapper must accept *args and **kwargs and return the result, or it breaks the function it decorates.

4. Where you will meet them

▶ YouTube reference — the video for this lesson

Flask and FastAPI use decorators for routes, pytest uses them for fixtures, and functools.lru_cache memoises expensive calls with one line. Recognising the pattern means you can read framework code instead of fearing it.

def timed(fn):
    def wrapper(*args, **kwargs):
        import time
        start = time.time()
        result = fn(*args, **kwargs)
        print(fn.__name__, "took", round(time.time() - start, 3), "s")
        return result
    return wrapper

When is a comprehension the wrong tool?

When the logic needs multiple statements, side effects, or error handling — then a plain loop is clearer and correct.

What must a decorator wrapper do to preserve the wrapped function's behaviour?

Accept *args and **kwargs, call the original, and return its result — otherwise arguments or return values are lost.

7 · Interview ▾

Explain what a decorator is and give a real use case.

A function that wraps another function to add behaviour like timing, logging or caching, applied with @ — e.g. Flask routes or lru_cache.

List comprehension vs generator expression — the difference?

A list comprehension builds the whole list in memory now; a generator expression yields items lazily, one at a time, using almost no memory.
